## 实测

| 场景 | 客户 | 客服 |
| --- | --- | --- |
| 禁用期间旧登录读/写客服接口 | 401 | 401 |
| 禁用期间密码登录 | 未签发令牌 | 未签发令牌 |
| 恢复启用后，原登录再次请求 | 401 | **200** |
| 恢复后重新登录 | 成功，原会话/历史不变 | 成功 |
| 单独签发短时 JWT：有效窗口内 / 过期后 | 200 / 401 | 200 / 401 |

[原始结果](identity-evidence-2026-10-20/identity-report.json)：completed=true、passed=false；25 项过程检查通过，恢复后旧登录状态单列 observations，不能用过程检查数掩盖失败。

禁用客户时检查历史、会话换取、回执和发送；禁用客服时检查身份、队列、历史及回复。全部在鉴权处拒绝，没有发送成功的测试聊天消息。重新登录后客户历史与原有历史精确一致。

## 原因与边界

- 原 `UserAuthServices::parseToken` 每次核对 status=1；当前登录在禁用期间被 HTTP 请求拒绝后，其令牌缓存被删除，所以本轮该客户旧登录不能复活。
- 原客服 `LoginServices::parseToken` 不核对启用状态。附加 `OmniChat::desk` 的回调补做状态检查，禁用时抛错拒绝，但不删除该令牌缓存或递增权限版本。账号恢复后，同一个旧令牌又通过检查。本轮 HTTP 200 与该代码路径一致。
- **不代表所有客户旧登录都已吊销**：禁用期间没有发请求的其他登录，本轮未覆盖；按当前实现，没有统一的账号级撤销版本，不能把一次请求触发的缓存删除视为全会话撤销。
- 状态切换直接针对本机测试账号的 status 字段，finally 恢复；不是原管理后台页面操作，不证明后台是否另有额外撤销动作。

## 过期测试的准确范围

通过原 JwtAuth 在服务端为这两个测试身份单独签发带随机标记的短时 JWT，遵守实现中的 60 秒时钟容差；有效窗口内先验证 200，等待 14 秒后验证 401。签名与缓存由原框架处理，不向浏览器或报告暴露签名密钥，不改全局有效期。

这证明真实 HTTP 认证链路在短时测试凭据过期后拒绝；不是等待默认 30 天，不是浏览器页面停止操作验收，也不独立区分 JWT 校验与令牌缓存过期各自贡献。页面到期反馈、重新登录后的浏览器缓存恢复仍待验证。

## 收尾

客户与客服原始 status 均为 1，测试后独立只读复查均为 1；restore_failures=[]，cleanup_failures=0。脚本对自行创建的登录逐个调用退出，包含已失效的测试凭据；不据清理计数宣称逐一完成二次鉴权。

无重启、无全局配置修改、无密码修改、无数据库表结构修改、无共享缓存清空、无真实模型调用。既有用户在禁用窗口发请求可能被原认证撤销登录，不能承诺不影响这些测试账号的其他已打开页面。

首次辅助程序仅按 account 查客户未找到，在任何状态修改前停止；按原登录的 account|phone 规则修正测试工具后完成。业务代码未调整。
