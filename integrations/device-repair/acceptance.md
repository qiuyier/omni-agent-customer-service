# 设备维修接入验收（2026-10-08）

本轮使用独立回环监听器、独立内存实例、两个模拟账号和本地模型协议替身。没有加载部署环境文件，没有连接 CRMEB、数据库或真实模型供应商。

## 通过范围

- 模拟登录后，宿主服务端交换受限身份；未登录、伪造客户字段、跨源请求被拒绝。
- 两个账号得到不同会话，用户乙不能用自己的登录 Cookie 搭配用户甲的聊天凭证。
- 维修报修与受理时间知识通过实际检索和模型协议进入请求，替身响应保存进历史。
- 相同事件重放返回相同结果，不重复调用模型；两个用户使用同名事件仍得到不同消息。
- 重新获取会话和退出后重新登录均恢复本进程内历史；退出后的旧登录不能继续访问。
- 用户甲、乙的历史和模型上下文互不串用；同一用户后续请求包含自己的已有历史。
- 无知识命中的问题返回替身的资料不足说明。三个新事件共三次本地模型请求。

## 验证命令

```sh
node --test integrations/device-repair/smoke.test.mjs
go test ./cmd/webchat-demo ./internal/webchat/... ./internal/bootstrap ./internal/ai/eino
```

两组检查通过。新脚本首次验证中发现替身未兼容数组形式的文本内容、断言误用 status 而非 outcome、退出预期误写成 200 而非 204；修正的是新增样例和断言，客服核心未改。沙箱内的构建缓存/标准库访问失败另在授权环境重跑通过，不计为业务通过或失败。

## 不能据此推断

本轮是现有通用模拟宿主的第二个业务场景，不是第二套真实生产系统的验收；无密码模拟登录不能直接用于生产。模型替身按参考资料生成固定输出，不能证明真实模型理解正确、拒答正确或抗注入安全。没有做浏览器视觉验收、网络中断、进程重启持久化、跨系统知识权限隔离或业务操作验收。

可确认的是：这一维修场景只新增知识、配置启动器和测试资料，复用了既有身份交换、聊天入口和客服核心，没有新增 CRMEB 字段依赖或行业核心分支。进一步验证真实回答质量时，应单独授权真实模型、小批量预算和逐题审阅。
