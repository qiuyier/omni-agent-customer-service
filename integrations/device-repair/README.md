# 设备维修：非 CRMEB 本地接入样例

目的：验证一个没有自带客服的模拟业务系统，可复用现有通用宿主、身份网关和聊天页，仅更换知识与模型配置；不改客服核心、CRMEB 或数据库。

## 启动与阅读顺序

在仓库根目录运行（需要 Go 和 Node.js 20+；首次构建可能下载 Go 依赖）：

```sh
node integrations/device-repair/demo.mjs
```

打开终端显示的回环地址，选择林澈或周宁，进入现有客服页。示例问题：“如何报修？”“受理时间是几点？”“火星天气怎么样？”。两个账号是无密码模拟身份，不是生产认证。

1. [知识样例](../../examples/knowledge/device-repair/faq.json)：明确标注虚构的维修资料。
2. [启动脚本](demo.mjs)：构建原有 webchat-demo，私有回环模型替身和独立内存实例；不读取 .env 或 CRMEB 配置，不使用付费模型。
3. [宿主适配](../../cmd/webchat-demo/host.go)：模拟登录 Cookie → 服务端身份交换 → 受限凭证 → 同域聊天代理。
4. [通用聊天接入说明](../../docs/browser-chat.md)：真实宿主需要实现的接口与安全边界。
5. [验收脚本](smoke.test.mjs)：通过实际 HTTP 监听器验证链路。

如需重新执行，必须显式允许付费模型调用（最多 7 次、不重试；每次新建归档目录）：

```sh
node integrations/device-repair/live-check.mjs --allow-model-api
```

该命令只从仓库根 .env 读取当前模型配置，不合并 .env.local；当前要求 chat_completions、HTTPS 端点及无自定义 Prompt。6 个场景各自使用独立内存实例，只有多轮场景保留自身历史。转发器使用 custom 兼容协议、指定模型和供应商默认生成参数；不是所有供应商专属配置的等价复现。凭证仅用于转发器内存，不写入报告。

本轮执行结果及未验证边界见[验收记录](acceptance.md)。

```sh
node --test integrations/device-repair/smoke.test.mjs
```

覆盖未登录拒绝、伪造客户字段拒绝、跨源拒绝、两个用户的凭证交叉使用拒绝、知识进入模型请求、回复保存、相同事件重放不再调用模型、重新获取会话后历史恢复、同名事件不串号、用户历史不进入另一用户的模型上下文、无匹配知识、退出后旧登录不能访问。

本地模型替身只回显本轮检索到的资料，没有语言理解能力；回答带显式替身标识。页面的 AI 模式表示经过模型协议链路，不代表真实供应商。测试通过证明接口接入和固定断言，不证明模型安全性或回答准确率。此处未执行真实浏览器视觉验收、付费模型评测、进程重启持久化或生产多租户验收。

## 结论边界与生产替换点

样例复用现有通用模拟宿主，而不是开发第二个生产账号系统；维修与电商的差异在知识数据，未新增行业分支。核心 Prompt 仍含订单/库存等举例，不能据此宣称所有措辞都已完全行业中立；本轮不改 Prompt。

真实接入时用业务系统已验证登录会话取代模拟账号；后端持有独立宿主凭证，不接受前端自报身份。独立部署应配置独立存储和授权知识，HTTPS/Secure Cookie、真实模型质量及业务操作权限需另行验收。浏览器用户隔离不等于多系统知识隔离，当前样例没有查询进度、收费、工单创建或人工接管工具。

退出 Ctrl+C 会停止两个本地服务并删除本次临时构建目录；内存会话不保留。不会停止现有 CRMEB 或其它客服实例。
