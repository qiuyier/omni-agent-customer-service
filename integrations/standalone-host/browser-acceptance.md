# 真实浏览器中断恢复验收

日期：2026-10-08。使用 Codex 内置浏览器实际点击、输入和刷新，不以 HTTP 脚本代替页面交互。隔离 PostgreSQL、独立 Node 后端、现有 Go 网关和固定回复，无外部模型调用。原前端与客服核心未修改。

[原始网络/进程记录与最终审阅结果](../../examples/archive/integration/standalone-host/2026-10-08T12-20-42-276Z-7b91f14c/report.json)保存本轮证据。passed 由实际浏览器观察、网络重放核对和数据库只读查询完成后确认；启动器采集本身不自动证明界面正确。

## 通过项目

| 操作 | 页面实际表现 | 后台核对 |
| --- | --- | --- |
| 甲登录、发送首条消息 | 消息和固定回复显示，元数据明确“持久化演示·模拟回复” | 保存一对消息 |
| SIGKILL 网关并重启，点击刷新 | 不要求重新登录，显示“消息记录已更新”，原历史保留 | GET401 → 身份交换200 → GET200，同一会话 |
| SIGKILL 业务后端并重启，点击刷新 | 提示登录失效，禁用输入/发送；返回站点重新选甲后原历史恢复 | GET401 → 身份交换401；重新登录后会话映射不变 |
| 成功发送的响应被断开 | 显示“等待确认”和重试按钮，不误报发送成功 | 代理在已收到成功回复后销毁下游连接 |
| 刷新待确认页面 | 保留待确认内容，明确不自动发送；可同时看到已保存历史 | 刷新只交换凭证、读取历史，没有自动POST消息 |
| 手动重试 | 待确认项消失，最终历史没有重复项 | 同一event_id/content，返回相同客户与回复ID |
| 保持甲的待确认标签页，另一个标签切换乙 | 原聊天页自动变为周宁，空历史、无甲待确认内容 | 乙取得独立会话；未发送甲的待确认事件 |
| 乙输入未发送草稿，再切甲 | 不携带乙草稿；甲恢复自己的历史和待确认项 | 甲仅在手动重试时再次发送原事件 |
| 再切回乙 | 乙仍为空历史，输入框为空 | 乙从未提交消息 |

两次断开响应分别测试“刷新后重试”和“跨账号切换后回原账号重试”。共5次POST、3个唯一事件，两次重试均复用原消息ID。数据库按本轮会话只读统计：甲3条customer、3条bot（各3个不同ID）；乙0条。确认不是页面隐藏了重复数据。

## 复现入口与范围

```sh
node integrations/standalone-host/browser-lab.mjs --allow-local-postgres
```

该本地验收工具沿用独立测试库及Docker Desktop上下文；终端输出浏览器地址。人工操作页面，终端支持 restart-gateway、restart-backend、drop-next、stop。前两项只结束并重启本轮子进程，drop-next 只断开下一次成功发送的响应。报告只保存模拟消息/事件/状态，不保存Cookie或Bearer凭证。它是测试专用故障代理，不可作为生产代理。

未切换电脑或浏览器的全局离线设置，也未验证所有断网时点。本轮断开的是已保存回复的响应，不能代表请求尚未到达、数据库事务中断、后台长时间断网、手机浏览器或多副本场景。通过的是当前内置浏览器、两个模拟账号和固定回复的页面恢复路径，不是生产认证或真实模型质量。

待确认消息按会话保留，不在切账号时永久删除；切换后不显示、不自动发送给新账号，切回原账号才恢复。响应丢失后刷新可能同时显示“已保存记录”和“待确认气泡”：后者仍等待原事件确认，不能仅凭内容相同就自动删除。手动重试完成后该气泡消失；这是安全恢复行为，不是重复入库。

本轮未发现需修正的前端功能问题。验收结束后已关闭临时标签页、所有本轮进程及独立PostgreSQL容器，保留测试数据卷和证据；未改动CRMEB或现有常驻服务。
