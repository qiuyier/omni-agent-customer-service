# 独立业务后端真实 AI 端到端验收

日期：2026-10-09（北京时间）。结果：本轮范围内通过。使用独立 Node 业务后端、现有 cmd/webchat-server、隔离 PostgreSQL、原聊天页和 glm-5.3-flash。没有修改 CRMEB，也没有新增电商专属逻辑。模型问答均由实际浏览器页面输入、点击、刷新及切换账号发起。

## 本轮实现

- 业务后端新增服务端可信 replyMode，默认 fake，非法值拒绝；浏览器不能覆盖。AI 发送等待120秒，覆盖 Go 网关110秒预算；修正原15秒等待不适合慢模型的问题。
- browser-lab.mjs 增加显式 --allow-real-ai，仅读取5个模型配置字段，保留独立数据库及随机宿主身份。使用默认系统提示和3条虚构通用资料；不更改 .env，不使用 embedding。
- 本机模型故障代理只转发到配置的 HTTPS 端点，用于计数和注入503；最多12次外部请求，不记录密钥/请求头/模型原始错误。成功响应丢失由业务侧故障代理注入。

## 数量与故障链证据

[网络、进程与模型调用记录](../../examples/archive/integration/standalone-host/2026-10-08T17-21-44-713Z-03201472/report.json)。目录名使用启动时UTC时间，启动于北京时间10月9日，浏览器验收在同日恢复并完成。

- 9次消息POST，6个唯一事件：额外3次来自同一密码问题的登录过期、注入503、成功回复重放。
- 密码事件状态链：401（登录过期）→503（本机模型故障）→200（真实生成成功，但丢弃响应）→200（重放）。后两次的客户ID、回复ID相同。
- 模型代理共7次请求：1次本机注入503、6次真实外部请求全部返回200；重放没有新增模型请求。
- PostgreSQL只读核对：甲5条customer、5条bot；乙1条customer、1条bot，各组不同消息ID数与行数一致。共12条消息，无重复入库。
- 恢复验收时测试数据库曾处于停止状态，历史GET返回503；启动专用容器后页面刷新恢复。测试登录也因停留过久到期，重新选择原账号后恢复原历史和待确认事件。这些记录保留，未伪装成全程无错误。
