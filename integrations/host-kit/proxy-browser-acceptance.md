# 共享代理真实浏览器回归（2026-10-16）

本轮验证提取共享代理后，办公门户与空白业务的既有客户/坐席流程是否仍然有效。使用内置浏览器、随机临时密码、真实本机 HTTP 与临时 Go 内存网关；回复为固定模拟内容，没有访问数据库、CRMEB 或真实模型。

暂扣器位于浏览器与业务服务之间，响应已经经过共享代理。上述暂扣实测证明客户端切号取消旧请求、旧记录不回填；不等价于浏览器现场验证代理内部的响应后身份检查。代理请求前后身份变化的拒绝由 proxy.test.mjs 自动测试覆盖。

## 发现的部署限制

两个样例复用相同登录 Cookie 名，并使用 `127.0.0.1` 与 Path=/。浏览器不按端口隔离 Cookie。最初同时登录两个样例时，后一次登录覆盖了另一系统的 Cookie，另一页正确进入身份失效状态，没有显示跨系统数据。

因此本次两个系统在同一浏览器中串行验收，不能据此宣称“同主机不同端口的并行部署已隔离”。实际部署必须设计 Cookie 命名/域与路径策略及服务端身份校验；不同端口不能作为登录 Cookie 的隔离边界。本轮没有修改业务登录 Cookie 或认证逻辑。

## 复现

先按 web/chat 的构建说明准备页面资源，然后在仓库根目录分别运行（同一浏览器中不要同时登录两个系统）：

```sh
node integrations/host-kit/proxy-browser-lab.mjs --allow-test-writes office
node integrations/host-kit/proxy-browser-lab.mjs --allow-test-writes fresh
```

每次终端输出本次随机地址和临时客户 lin/zhou、坐席 staff 密码；不要把密码写入文档。通过页面正常登录和操作，不注入浏览器身份。

终端控制命令：`hold` 暂扣下一次历史 GET，待 `captured` 后再切号；`release` 放行；`status` 查看暂扣状态；`restart` 重建业务和适配器；`stop` 关闭临时服务并清理夹具。没有新增 HTTP 管理入口。完成后关闭任务创建的浏览器页。

## 修改范围

新增测试启动器，并扩展既有 fresh-onboarding 夹具以选择 office/fresh；默认行为仍为 fresh。没有修改生产代理、共享页面或 Go 核心。本轮浏览器临时服务均已停止。
