# 登录到期与恢复验收（2026-10-23）

## 结论

本轮可控复现的 401 错误码是 host_login_required：模拟业务站点登录过期，不能再换取聊天凭证。不是模型错误，也不是应当无限重试的聊天令牌续期失败。

宿主身份查询 /host/me 在未登录时返回 200、user=null，随后 /host/chat-session 返回 401 是现有协议设计。模拟登录有效期 30 分钟。上一轮原始报告没有错误码，不能事后把其具体 401 原因断言为已查明；本轮证明了到期能够复现相同现象，且恢复路径正常。

## 真实浏览器验收

1. A 登录，发送 LOGIN-EXPIRY-20261023 同账号恢复测试；本机 mock 故障注入，原消息已接收、回复失败。
2. 私有实验命令 expire-login 将业务宿主时钟临时推进 1800001ms，通过正常会话读取执行过期清理，再恢复时钟。没有删除数据库、改变系统时间或开放 HTTP 故障接口。
3. 页面自动检测登录失效，清除当前显示的身份/历史，禁用输入与发送，无重试入口。原 pending 仍按会话保留于当前标签页。
4. 同标签页返回站点重新选 A：恢复相同 conversation_id、历史和原问题重试入口，没有自动消息 POST。
5. 切换 B：不同 conversation_id，空历史、空输入，无 A 的重试入口。再切回 A，原事件仍可恢复。
6. 恢复模拟模型并启用 mock-fast 后，明确点击重试；event_id 仍为 03e6b246-4556-43c0-813a-ab88ed764e00，最终只有一条客户消息和一条机器人回复。

数据库只读查询：A customer=1、bot=1；B 消息=0。登录/到期/切换账号期间只有最初一次消息 POST；最终手动重试新增第二次 POST，同事件。外部模型请求 0。

## 改动与边界

没有修改通用客服应用或认证策略。修改的是隔离测试工具：业务 worker 的私有父进程 IPC 到期命令、脱敏错误码采集、退出时关闭 IPC；新增 host.test.mjs 断言，验证到期后身份为空、换凭证/发送返回401、重登可恢复、旧登录不能复用。

该命令使当前实验 worker 内所有模拟客户登录过期，供隔离验收使用，不是生产管理能力。真实浏览器 Cookie 自然到期、外部业务 SSO、跨设备恢复、生成中恰好到期均不是本轮验证范围。到期采用宿主时钟注入，不冒充真实等待30分钟或浏览器时间推进。
