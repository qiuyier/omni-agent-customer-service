# 刷新后恢复未完成回复（2026-10-23）

## 完成内容

消息回执增加 reply_status 和 retry_allowed，不改变 accepted 的原意。

| 回执 | 前端恢复行为 |
| --- | --- |
| not_replied / true | 原问题是机器人会话最新客户消息、尚无关联机器人回复；保留本地原事件并显示“重试回复” |
| replied / false | 已有关联回复，清理本地待恢复记录，不再生成 |
| unavailable / false | 已转人工、关闭或被后续客户问题替代；清理本地恢复记录，不再生成 |
| 字段缺失、组合不合法或核验失败 | 保留记录，不授权回复重试 |

尚无回复不等于生成已失败，也可能仍有请求处理中。点击重试前再查询一次回执；复用原消息 event_id 和正文，继续走服务端忙碌限制、最新问题检查、身份隔离及回复去重。回执只是状态快照，不是绕过并发检查的授权。页面初始化、刷新和回执查询均不自动生成回复。

转人工后按钮立即禁用，刷新后移除恢复入口。服务端最终检查可挡住“检查允许后又转人工/关闭”的竞态。未知旧版回执不会被猜测成可以重试；旧服务端应先升级，或保持前端旧版，混合部署时新版页面会保守保留未知状态。

## 范围与清理

恢复沿用现有 sessionStorage 中的原消息事件：支持同一浏览器标签页刷新，不声称支持清空存储、跨设备或任意历史失败问题恢复。未增加后台自动补答任务、重试队列或真实模型超时验收。

刷新后历史中的已接收问题和恢复提示可能同时显示，这是本地恢复提示，不是数据库重复保存。机器人已有回复或不再允许处理时，恢复提示被清除。

共享源码与四个通用示例 JavaScript 已重建。只更新仓库内 CRMEB 协议测试样例，未修改外部 CRMEB 系统或部署其页面。没有发布。

测试网关、宿主、本机 mock 和 PostgreSQL 服务已停止；沿用的 standalone 验收持久卷与虚构数据保留，没有删除既有数据库。
