# 管理知识到客服回答：真实进程验收

日期：2026-11-02。目标是验证管理操作确实改变客服检索，而非仅改变页面状态。

## 链路与安全范围

管理页面 / 管理 API → 独立 knowledge-admin 进程 → 新建 PostgreSQL 16 → 独立 webchat-server 进程 → loopback Chat Completions 模拟模型 → 已保存的客服回复。

新增脚本 `scripts/managed_knowledge_e2e.mjs`，只接受新建测试容器和卷，不接受用户 DSN、模型 URL 或业务配置。子进程环境使用白名单，不读取项目 .env，不继承真实模型凭据；模拟模型仅监听 127.0.0.1，校验固定测试协议与非生产凭据。运行时生成账号哈希文件权限 0600，结束删除；临时账号仅供本次测试，没有生产默认账号。

```sh
# 自动模式：独立数据库、真实进程、受保护管理 API、真实 HTTP 和模型协议
node scripts/managed_knowledge_e2e.mjs --allow-test-writes

# 浏览器模式：脚本先建立旧版，等待人工/浏览器执行保存、发布、回退
node scripts/managed_knowledge_e2e.mjs --allow-test-writes --browser
```

需要 Docker Desktop、Go 和 Node。数据库容器使用 postgres:16-alpine，独立随机容器名和卷名，并绑定本轮唯一标签；清理前必须核对标签。仅在本轮卷执行迁移，退出清理容器与卷（虚构数据不可恢复）。不会访问 CRMEB/PHP74、已有数据库或真实模型。不会提交、推送、发布版本。

浏览器模式打印随机本机入口与公开虚构测试账号，登录后将答案替换为终端给定的新版文本，依次保存草稿、发布、回退旧版；每步应等待终端 PASS 后再继续。每阶段最长等待 10 分钟，超时失败并清理。脚本在回退验证后自动重启并清理，因此该浏览器地址不是长期演示服务。

## 检查内容

| 阶段 | 管理状态 | 实际模型知识与持久化回复 |
| --- | --- | --- |
| 初始旧版 | r2，旧版发布 | 旧版 09:00–17:00 |
| 保存新草稿 | r3，旧版仍发布 | 仍为旧版 |
| 发布新版 | r4，新版发布 | 新版 10:00–18:00 |
| 回退旧版 | r5，草稿仍为新版 | 恢复旧版 |
| 重启管理、客服进程及数据库容器 | 完整 state 与 r5 深度相等 | 仍为旧版 |

每阶段创建独立虚构客户会话，向客服网关发新问题。断言模型请求中只有一个以 user 角色传递的知识参考封套、其中内容等于预期；本地模型返回该资料，继续通过聊天历史接口断言 reply_message_id 对应回复已持久化且内容一致。每阶段恰好一次本地模型请求，全程成功运行共 5 次；不验证真实模型的语言质量或同一旧会话的历史影响。

重启后还检查旧管理员 Cookie 返回 401，重新登录后完整管理状态不变。聊天网关不开放管理路径。资源预检是只读的，不调用模型或重做迁移。
