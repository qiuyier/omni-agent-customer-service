# v1.2.0 — 知识改进闭环

发布日期：2026-11-11（Asia/Shanghai）。通用客服源码发布，公开状态以 GitHub 标签及 Release 为准；不构成公网生产开放批准。

## 新增能力

- 默认关闭的 managed FAQ 未命中问题采集；管理员可筛选、忽略、重新待处理、转本地 FAQ 草稿，人工保存和发布后关联已发布 FAQ 标记解决。
- 已发布知识只读检索验证，区分预期命中、其他命中及未命中；绑定版本，不自动解决、不生成答案、不调用模型。
- 无问题正文的采集与清理运行状态，以及只读队列预检、排错和隔离完整链路验收。

能力保持业务通用，不依赖 CRMEB。仍是单业务独立实例、小规模关键词 FAQ，不是多租户平台或语义检索。

## 隐私与启用

采集默认关闭，显式启用前须确认资料授权和访问、备份保留政策。规则脱敏不是匿名化保证，姓名、地址等仍可能保留。最多 500 条、单条正文最多 512 字符，以首次出现计 7 天可访问期限；物理清理在启动和周期任务中尽力执行，不覆盖备份、WAL 或停机数据。不存客户/会话关联或完整对话。

详见 [功能与隐私](knowledge-feedback.md)、[运行说明](knowledge-feedback-operations.md)、[参考部署](../deploy/reference/KNOWLEDGE.md)。默认回复模式不变，不自动启用真实模型。

## 升级与回退

**从 v1.1.0 的 schema 3 升至 schema 4，即使 fake 回复也需要显式迁移。** 维护窗口停止写入，私密备份专用数据库、配置和旧程序，先在独立恢复副本验收再迁移目标库。程序启动不会自动迁移，不要重新 init、删卷或用示例密码覆盖配置。

v1.1.0 不能直接连接 schema 4。降回旧应用需要停止新写入并保全升级后数据，恢复升级前 schema 3 备份及匹配的旧程序/配置后验收切换；备份后的消息和知识操作不在旧备份中，必须另行处理。没有通用无损降级。关闭采集不等于降级或删除已有资料。

详细步骤见 [候选阶段升级指南](feedback-release-candidate.md)。该文保留历史候选状态，最终发布证据以附件 VERIFICATION.json 为准。

## 验证与附件

v1.1.0 旧程序写入数据、3→4 迁移及重复迁移、会话继续接待、知识发布、数据库/进程重启，以及恢复到另一 schema 3 数据库后旧程序可用的 10 项专项已通过。另有默认恢复回归、Go 测试、vet、模块校验。真实模型效果、生产库副本和浏览器人工项不能由这些自动化结果替代。

源码附件从最终提交导出，包含源码、已构建页面和许可，不含私密配置、数据库、node_modules 或预编译 Go 二进制。下载后执行 `shasum -a 256 -c SHA256SUMS`，核对 SOURCE-MANIFEST.json 和 VERIFICATION.json。自有代码 MIT，第三方各遵其许可。有限敏感模式扫描不是全面秘密或历史审计。
