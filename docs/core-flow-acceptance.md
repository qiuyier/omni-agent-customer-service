## 浏览器操作与证据

1. 启动 `node integrations/standalone-host/browser-lab.mjs --allow-local-postgres --allow-real-ai --allow-human-desk`。真实调用需单独授权额度。
2. 在启动输出的地址选择林澈，进入 `/chat/`，询问服务台开放时间。
3. 点击“申请人工处理”；在 `/desk/` 选择乔杉，刷新队列、打开对应会话并接管。
4. 发送明确标记的人工测试回复；客户刷新后显示“人工坐席”，内容一致。
5. 坐席结束并关闭，客户发送框禁用；点击“发起新咨询”，新会话初始为空。
6. 新咨询询问找回密码，收到真实 AI 回复；点击“查看上一轮记录”，旧 AI/人工消息仅出现在只读历史区。
7. 输入 `stop` 停止实验服务并保留数据库卷。

本轮机器报告：`examples/archive/integration/standalone-host/2026-10-24T06-02-49-754Z-33a63c01/report.json`。报告中的 `passed:null` 是实验工具默认人工待审字段；本文件记录实际人工审阅结果，不改写原始报告。启动后浏览器工具返回曾长时间延迟，实际模型请求为 UTC 14:18，不能把整段运行时长当作模型延迟。

## CRMEB 首次失败及修正

首次运行 `integrations/crmeb/human_check.mjs`：登录、角色隔离、双客户隔离等 10 项通过，在 `customer_message` 失败。复核发现账号当前咨询已经关闭，旧脚本没有检查初始状态。

本轮只改验收脚本：先读历史状态；仅当已关闭时通过 consultations 接口新建、重新绑定；如果处于等待人工或人工处理中则停止，不抢占或关闭别人正在处理的会话。发送失败现在报告 HTTP 状态，不输出凭据。

修正后实际执行了 `start_after_existing_closed_round` 和 `bind_fresh_round`，32 项通过：真实登录、角色隔离、双客户隔离、正常发送、转人工、队列、接管前禁止回复、接管、历史/已读、人工回复幂等、客户仅收到一次、另一客户不可读、关闭后禁止发送、新咨询、旧凭据失效、新咨询为空、旧历史保留、客服退出后拒绝。创建的业务登录由脚本退出。

没有修改通用客服核心、CRMEB 业务代码、业务知识或模型配置；没有重启 PHP74，也没有删除历史或数据库。CRMEB 仍保留原服务运行；独立实验子进程与专用测试 PostgreSQL 已停止，卷保留。
