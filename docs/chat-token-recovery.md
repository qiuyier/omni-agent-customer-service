# 聊天令牌恢复修复（2026-10-22）

## 修复内容

旧版业务身份包装层把所有 401 直接当作登录失效，导致聊天协议已有的令牌更新流程被页面卸载打断。现在只对客户聊天操作的第一次请求允许核验业务身份：同一客户、同一登录版本才交还协议层更新聊天令牌，并使用原 event_id、原正文重试一次。

不是自动重发待确认消息：用户仍须点击重试。后台历史查询可更新令牌，但不会发送待确认消息。身份核验不携带聊天 bearer，内部恢复标记不传入真实 fetch。

退出、换号或登录版本改变会停止恢复；身份服务网络异常、限流或无效响应不授权重发。令牌签发拒绝、第二次聊天请求仍返回 401 时立即失效，不循环恢复。新令牌绑定不同咨询轮次时拒绝旧消息重放。员工工作台、普通业务请求不使用此例外。

## 本轮验收

- 网页逻辑测试 92 项通过，其中新增组合恢复测试 16 项。
- 分容器与两个业务接入集成测试通过（完整计数见交付说明）。
- 三个使用共享业务身份边界的示例页面已重建：fresh-onboarding、business-login、office-portal。无样式调整。
- 独立容器轮换真实客户端证书与宿主密钥，故意提交无效配置，再激活新配置；旧证书/旧密钥均被拒绝。
- 浏览器轮换前发送 BROWSER-RENEW-BEFORE；中断时 BROWSER-RENEW-PENDING 显示待确认；激活后仅点击一次重试，显示“消息已发送”，无需重新登录。
- PostgreSQL 只读核对两条标记各一份、属于同一会话；未出现重复保存。
- 实际点击退出业务登录后返回登录页，聊天内容消失。
- 专用容器、网络、镜像与临时资料已清理。未修改 CRMEB，未调用真实模型，未推进发布。

[自动验收报告](evidence/chat-token-recovery-2026-10-22.json) 的 browser_verified 保持 false：脚本不会把打开浏览器等同于验收通过；以上浏览器操作由本轮人工式 UI 操作单独核验。截图位于 /tmp/omni-chat-renewal-20261022.png（临时本机文件）。

旧轮换文档中“两次点击”的叙述保留为历史事实，本修复替代该已知问题。
