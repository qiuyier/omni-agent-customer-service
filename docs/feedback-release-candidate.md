## 冻结范围

本轮不增加业务功能。相对 v1.1.0，候选范围为：默认关闭的 managed FAQ 未命中问题采集、人工转草稿/发布/标记解决、已发布知识只读检索验证，以及无问题正文的运行状态与排错指引。保持通用客服能力，不绑定 CRMEB。

仍是单业务独立实例、小规模关键词 FAQ；不是多租户平台、语义检索或自动知识生成。检索验证不调用模型、不自动解决问题，也不是回答质量评价。

采集须显式开启；规则脱敏不是匿名化保证，姓名、地址等仍可能保留。队列最多 500 条，单条正文最多 512 字符，以首次出现计 7 天可访问期限；物理清理是启动/周期尽力执行，不覆盖备份、WAL 或停机数据。运维方必须先确定资料授权、访问和备份保留政策。详见 [功能与隐私](knowledge-feedback.md)、[运行说明](knowledge-feedback-operations.md)。

## v1.1.0 升级与应用回退

1. 核对正式发布标签与校验和，安排维护窗口，停止客服及管理写入；私密备份专用库、配置及 v1.1.0 程序。不要覆盖配置或复用示例密码。
2. 先把备份恢复到独立数据库，使用新 migrate 从 schema 3 升至 4；检查会话、消息、回执、人工状态、已发布知识和未发布草稿。
3. 恢复副本验收通过后，才在维护窗口对目标库执行同样迁移并启动新程序。启动不会自动迁移；即使 fake 回复也需要匹配的新 schema。采集保持默认关闭，需要时再单独开启。
4. 要回到 v1.1.0，必须停止新程序写入并保全升级后数据，再恢复升级前 schema 3 备份，使用匹配的旧程序/配置验收后切换。不能直接把旧程序连到 schema 4，也不能手改版本账本。

恢复旧备份会丢失备份之后的新消息和知识操作，须事先处理这一时间段的数据；本轮没有提供无损降级。关闭采集或关闭 AI 不等于降级，也不会自动清除已有数据。
