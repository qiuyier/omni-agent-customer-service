# 历史消息分页与未读定位

通用坐席工作台能力，不依赖 CRMEB。解决旧版本只能展示最近100条消息、较早未读无法查看的问题。客户聊天页和“上一轮记录”接口不在本轮改动范围内。

## 使用方式

- 初次打开会话仍读取最新一页，最多100条、正文总预算128 KiB。
- “加载更早消息”把上一页添加到当前列表顶部，按消息ID去重，保留当前阅读消息在滚动区域内的位置。
- “定位未读消息”读取最早未读客户消息所在的起始页，并把键盘焦点和滚动位置移到该消息。同会话回复草稿不变；显式切换其他会话仍使用原有草稿/待确认隔离规则。
- 新消息从当前已加载列表末尾继续读取。若积压超过一页，后续轮询逐页补齐，也可点击“加载后续消息”，不会直接跳到最新100条而漏掉中间消息。
- 页面内合并已加载历史；刷新整个网页不保存这份缓存，重新打开会话从最新一页开始。普通“刷新队列”保留已加载历史和草稿。
- 未读确认仍按实际进入视口的消息ID发送。读取/定位接口本身不清未读；成功显示之后，可见的消息才由独立已读机制确认。没有“全部已读”操作。

## 接口

POST /internal/chat/desk/action 的 history 可选且互斥：

| 字段 | 含义 |
| --- | --- |
| before_message_id | 从此ID之前向前取一页，不包含该消息 |
| after_message_id | 从此ID之后向后取一页，不包含该消息 |
| from_message_id | 从此ID开始向后取一页，包含该消息；供未读定位使用 |
| 均不传 | 最新一页 |

返回消息始终按存储追加顺序从旧到新排列，has_older / has_newer 表示对应方向还有消息。队列与历史的 first_unread_id 是当前坐席最早未读客户消息ID，为空时不显示定位按钮。

消息ID是已授权会话内的锚点，不按时间戳或ID字典顺序分页。锚点不存在、属于其他会话或不是公开消息时返回400；会话权限检查先执行，跨来源/非本人接管会话仍拒绝。游标不能用于 claim/reply/read/close。没有增加数据库迁移，仍使用版本2。

超出单页正文预算的单条旧消息只展示有效UTF-8片段并标明截断，避免分页卡死；截断的客户消息不自动确认已读。浏览器正常发送仍有原有4000字节限制。

## 实现边界

后续已补[PostgreSQL数据库分页和未读汇总优化](database-desk-pagination.md)：内置PostgreSQL工作台路径直接查询当前页和摘要，不再把整段正文取回Go。内存及自定义仓库兼容路径仍可使用完整历史裁剪。浏览器当前会话已加载消息保存在内存中，没有虚拟列表或缓存容量上限；大规模/超长会话的查询与渲染负载仍需单独验收。

定位操作可能重建当前历史窗口；没有持久化阅读位置，没有全文搜索、消息编辑/删除，也不提供生产认证或实时推送承诺。外部其他标签页标记已读后，服务端计数/最早未读会更新；本页缓存中的旧ID确认仍幂等。
