# 浏览器重试恢复验收（2026-10-23）

## 结果

真实内置浏览器、模拟账号、本机 mock、独立 PostgreSQL。没有外部模型请求。完成可执行的跨页面人工流转、刷新恢复、服务链路中断和手动重试；不宣称完整双标签页同事件重试验收通过。

| 场景 | 页面观察与后台核对 |
| --- | --- |
| 原页生成失败后，新开同账号第二页 | 第二页能看到问题历史，但没有原事件的重试按钮。pending 使用 sessionStorage，不跨新标签页共享。没有通过注入存储伪造双页状态。 |
| 第二页申请人工 | 原页未手动刷新，自动显示等待人工，清除原重试入口。 |
| 坐席页面接管并关闭 | 坐席显示已结束；客户刷新后会话已结束，发送禁用，旧重试入口不恢复。数据库客户消息 1、机器人回复 0。 |
| 未完成回复刷新 | 原事件恢复，仍需明确点击，刷新未自动发送。 |
| 专用网关停止后点击重试 | 原版把已送达错误降为等待确认。未产生消息 POST，但提示不准确。已修复为保留已送达，核验失败禁用重试。修复版已浏览器复测。 |
| 网关恢复、刷新后手动重试 | 重新允许重试；原 event_id 不变，最终 1 条客户消息、1 条机器人回复。 |

中断通过停止本轮专用网关进程实现；没有切换操作系统或浏览器全局离线模式。恢复时观察到轮询失败退避，最终采用手动刷新确认恢复，因此不宣称本轮实测了无人操作的自动恢复完成时限。没有单独证明后台标签页 visibility 隐藏/恢复行为。

## 修复

web/chat/src/app.jsx 的 send 不再在每次重试时无条件清空 pendingAccepted；仅新事件清空它。每次开始发送先撤销旧 retry_allowed，之后依赖新回执重新判断。已确认送达与回复资格分开保存。新增源代码约束回归，并保留原回执、事件去重和服务端并发保护。

实验工具新增 mock-fast/mock-slow，仅在 --mock-slow-ai 下生效，分别设置后续模拟回复等待 200ms/90s；仍可 release-model 提前结束。首次慢模型尝试被请求超时取消（mock 499，HTTP 503），不是成功回复。快速模式仅用于稳定验证成功恢复，不验证真实模型时延。

相关网页与参数测试 113 项通过；四个通用前端产物重建，修复版实际加载验收。没有修改外部 CRMEB 或 PHP74，没有发布。
