# 未命中问题收集（待发布）

仅用于单业务实例的 managed 关键词 FAQ：真实客服消息检索成功但零命中时，尽力记录规则脱敏后的问题。检索失败、命中、启动检查、管理员试检索和批量检查不收集。采集失败不改变原检索结果；一次采集最多使用剩余请求时间中的 100 ms，不自动重试。不是回答质量评分，也不代表模型回答错误。

## 开启与升级

默认关闭，不继承其他 AI 开关。部署方确认有权收集文本、完成用户告知并评估隐私风险后，才可设置 `WEBCHAT_KNOWLEDGE_FEEDBACK=true`。只接受 `true` / `false`；开启要求 `WEBCHAT_KNOWLEDGE_SOURCE=managed`、AI 模式和单宿主。此开关只控制后续采集，不删除已有记录。

参考部署可在原有私密 `ai-managed.json` 中增加布尔字段 `"captureUnmatched": true`，再按原流程检查并启动 managed 模式；省略或 false 均不采集。普通 ai.json 不支持该字段。不要放入业务凭证或真实示例问题。

本轮 schema 从 3 升到 4，新增独立 `knowledge_feedback` 表。先按既有升级流程备份并停服，再显式运行迁移命令，随后启动新版本。服务不会自行迁移。本轮开发未迁移任何现有业务库。旧应用要求精确 schema 版本，不能直接搭配新库；回退应走完整备份恢复，不要随意降级表。

## 隐私及保留边界

检索剩余预算少于 200 ms 时不采集，避免采集写入挤占检索完成检查；完整问题只在队列中保留，转草稿时标题取前 128 字符（FAQ 标题限制），仍须人工审核补全。

- 存储字段仅有随机问题 ID、脱敏问题、出现次数、处理状态/修订号、关联 FAQ ID、首次/最近出现和到期时间；没有客户 ID、会话 ID、完整对话或原始问题哈希。
- 规则替换邮箱、HTTP(S) 链接、部分连续数字/电话格式、带常见标签的密码和令牌。姓名、地址、无标签密钥、特殊格式个人资料仍可能残留。**规则脱敏不能保证匿名化，也不能替代部署方的合规审查。**
- 每条最多 512 字符，全实例最多 500 条；队列满时忽略新问题。相同脱敏文本合并计数，最多 100 万次；不同客户的问题可能被合并。已处理问题重复出现不自动重新打开。
- 首次记录后 7 天到期，重复出现不续期。到期后列表和状态操作立即不可访问。网关/管理进程启动时及每小时尽力物理清理；持续运行且数据库正常时通常最迟在到期后 1 小时删除。停机、故障及备份/WAL 副本可能延长物理保留，部署方需另外安排备份到期策略和监控。不能把它宣传为所有介质严格 7 天销毁。
- 浏览器不把队列写入持久存储；管理员显式读取后才能查看。主动将问题纳入 FAQ 后，其文本按知识版本/审计保留规则存储，不再受队列 7 天期限约束；保存前需再次检查个人资料。

## 管理流程

独立知识管理页的“未命中问题”区域：读取列表 → 按待处理/已忽略/已解决筛选 → 转为本地 FAQ 草稿 → 人工补齐可靠答案、来源和关键词 → 保存、审核、发布 → 关联当前已发布 FAQ 并标记解决。不会自动生成答案、保存或发布。也可直接忽略或重新标记待处理。

读取使用 `knowledge.read`；状态处理和转草稿需要 `knowledge.edit`，发布仍需要独立 `knowledge.publish`。状态写入使用问题修订号避免并发覆盖；解决时数据库核对 FAQ 存在于当前发布版本，不证明其语义上正确。状态变更不写入长期知识审计，避免队列文本和身份信息长期滞留。

接口仅在独立管理入口：`GET /internal/knowledge/feedback`，`POST /internal/knowledge/feedback/status`（id/revision/status/faq_id）。沿用原有会话、同源、权限和 no-store 边界；客户/坐席接口不暴露队列。状态更新结果不明确时先重新读取核对，禁止自动重放。
