## 可重复运行

```sh
node --test scripts/knowledge_feedback_flow_check.test.mjs
node scripts/knowledge_feedback_flow_check.mjs --allow-test-writes
```

需要本机 Docker `desktop-linux`、Go、Node 和 `postgres:16.15-bookworm` 镜像。只接受精确的 `--allow-test-writes`，帮助和错误参数不创建资源。不会读取已有 DATABASE_URL、模型配置、管理员配置或业务库；启动参数从白名单环境和脚本新建资源生成。

每次创建随机命名、带唯一归属标签的测试容器和数据卷，只在这些资源上迁移 schema 4、写入虚构记录和模拟过期。模型服务固定绑定随机 loopback 端口，只返回本机固定模拟文本，没有供应商调用。报告写入系统临时目录 `omni-feedback-flow-*`，仅保存检查结果、代码基线、请求计数和清理状态；不保存消息正文、Cookie、数据库口令或 API 凭证。

结束时停止子进程和模拟模型，核对 Docker 归属标签后删除本次容器与卷，删除临时账号文件。清理失败会将报告标为失败，不应只看前面的 PASS 行。SIGINT/SIGTERM 会中断子进程并进入清理；强制杀死或主机崩溃不保证执行清理，需按报告目录和唯一资源标签人工核对。

## 已通过检查

1. 关闭采集时仍正常生成模拟回复，问题队列为空。
2. 开启采集后真实未命中生成脱敏记录；启动检查不会生成问题或调用模型。
3. 同一消息事件重放不重复计数，也不重复请求模型。
4. 前端控制器转出的草稿答案为空，尚未保存；补齐并保存后，未发布知识仍不进入模型上下文。
5. 发布后验证命中预期 FAQ；验证不调用模型、不自动解决问题。
6. 显式人工解决后，状态及关联 FAQ 持久化。
7. 旧问题修订号、旧知识修订号、只读账号尝试修改/发布均被拒绝。
8. 客户再次提问时，新增 FAQ 答案实际出现在模拟模型收到的检索上下文；不增加未命中计数。
9. 同时停止网关/管理服务并重启 PostgreSQL 后，问题状态、知识版本、会话历史逐项保持一致；旧管理会话失效，新登录后可读；再次提问仍带新知识。
10. 仅在脚本自有库将时间前移模拟过期：问题列表不可见，验证和状态操作被拒绝。
11. 采集关闭时重启网关，过期问题仍由启动清理任务从表中删除。

共 **5 次本机模拟模型请求、0 次外部模型请求**。容器和数据卷均清理成功。参数安全测试 2 项通过。

## 不代表什么

- 本轮使用真实 HTTP 和前端控制器，但没有重新操作浏览器 DOM；页面布局和按钮人工验收沿用上一轮，不能把本报告描述成新的浏览器端到端录像或验收。
- 检查的是检索上下文包含新知识，不证明真实模型最终答案正确，也不证明所有自然语言表述均会命中。
- 过期采用测试库时间字段调整，没有实际等待 7 天；未验证数据库故障期间、备份/WAL 或其他副本的销毁时间。
- 没有操作现有部署、CRMEB/PHP74，没有开启现有采集开关，没有提交、推送或发布版本。
