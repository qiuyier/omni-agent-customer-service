## 面向真实客户开放前的目标环境门槛

这些是具体部署的开放条件，不要求每次发布源码都先建一套生产环境，也不能移入发布后优化录后跳过。

- 真实身份、授权、退出/禁用生效、双客户隔离和私有 API 不可绕过，在目标系统验证。
- HTTPS、受保护的网络、独立密钥、客服专用数据库、最小权限、日志脱敏已配置。
- 备份可恢复，进程/业务适配重启可恢复；明确操作人、停止入口与回退方式，不删除数据作为回退。
- 按实际规模约定容量和错误处理方式，基本就绪/错误监测与响应责任明确；不是无限规模承诺。
- 若启用 AI：使用经过确认的业务资料、数据授权、费用边界和未知问题处理方式，目标模型小样本复验，不以 fake 通过替代。

责任分配：业务身份/坐席由接入方负责；数据库/网络/备份与运行由部署负责人负责；网关和参考适配由项目维护方负责。当前生产目标与负责人未指定，因此不作生产开放批准。

## 明确不扩展的范围

订单、退款、预约等业务执行工具、多宿主共享 AI/知识隔离不是当前默认承诺。不因 CRMEB 是示例就把核心做成电商客服。GitHub 云端 CI 首跑及后续非阻断体验完善继续按 [优化录](post-1.0.0-improvements.md)安排，不作为本轮开发。
