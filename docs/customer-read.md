# 客户本人发货状态查询（未发布）

这是宿主提供的一项窄范围能力，不是任意数据库问答或运营分析。CRMEB 工作台无需改数据库结构。它不查询物流轨迹、商品明细或收货地址，不会修改订单。

在配套网关升级后，将仓库里的 Bridge.php、CustomerRead.php、OrderShipping.php、Transport.php 安装至宿主 extend/omni_chat，同步更新 OmniChat.php 控制器及客户侧静态资源，在**私有**实例配置显式设置布尔值 order_shipping_lookup=true。缺省关闭；用 false 关闭新查询，不删除已有会话记录。本轮没有在原站开启。 通用回调和验收入口见[客户查询 v1 契约](customer-read-contract.md)。

- “帮我看看最后买的那单寄出来没”直接查本人最近订单；“订单号LABA1发货了吗？”按本人及单号查询。没有明确订单的“我的订单发货了吗？”先追问，不读订单表。
- 紧接追问可以回复“最近那笔”或提供单号。适配器通过已绑定的会话凭据读取历史，只有机器人接待状态、最后两条为同一咨询的客户提问及对应追问回复，才处理省略句。没有待回答的追问时不查，换话题、转人工或新咨询不延续追问。不新增跨客户缓存或数据库表；核对历史依赖一次额外网关请求。
- “你们一般多久发货？”等规则问题仍走普通聊天/已配置知识问答，不查个人订单。当前实现是有限的中文句式识别，不调用模型分类，也不保证覆盖方言或任意改写。未配置知识的固定回复模式不会因此获得发货政策知识。
- 最近按 add_time、id 倒序；指定单号与已验证 UID 一起过滤，排除用户/后台已删除订单。无权查看和不存在均返回同一答复。退款、非配送和不认识的状态不猜测。
- 宿主只将固定答复传回网关，不传表、行、备注或凭据。它仍会作为普通客服答复保存，后续如启用 AI，历史对话可能进入模型上下文。客户自己输入的单号也属于聊天正文，并非匿名查询。
- 宿主在已验证客户登录和会话绑定后查询；已被人工接管的消息仍沿用网关原规则，不发自动回复。当前实现可能在网关检查会话状态前执行一次只读查询；重复投递也可能重读，但不得改写已保存答复。
- 网关对附带 host_reply 的消息要求来源匹配的签名：HMAC-SHA256，密钥为 SHA256(宿主密钥) 的原始字节；输入为 ASCII omni-host-reply-v1 后依次拼接客户 chat token、event_id、问题正文、答复各自的 SHA256 原始字节。证明通过 X-Omni-Reply-Proof 发送；宿主密钥及其摘要都应作为秘密保护。公共客户端不应接触签名材料。该协议只用于受信任宿主，不让客户或模型提供已核实的答复。
- 其他业务可以在自己的适配器读取自己的数据并生成限定答复，Go 核心不需要认识订单字段。此实现不是工具注册表，也不执行模型输出的 SQL。无调用关联的原始 tool 消息从模型历史中过滤，不作系统指令。

验收：隔离 PHP 7.4.33 原登录 HTTP、MySQL 虚构订单、PostgreSQL 会话及 fake 网关。验证本人最新未发货（即使他人订单更晚）、数据库改为已发货后用新事件查到新状态、重发旧事件仍返回原答复、指定他人单号无可见记录、订单表临时不可用时明确查询失败。人工接管/关闭和坐席隔离回归通过，临时资源已清理。未执行原站部署或浏览器点击验收。
