# 明确发起新咨询

这是通用网页渠道能力，不依赖 CRMEB，也不重开已关闭会话。独立 Node 示例聊天页在会话关闭后显示“发起新咨询”；新轮次为 bot_active，实际回复使用当前服务的 fake/AI 配置。创建本身不调用模型、不发送消息。

## 协议与隔离

- `POST /chat/v1/consultations`：旧轮次客户凭证，仅允许 `{}`。必须已关闭；旧会话 ID 决定唯一后继 ID，数据库事务锁串行化并发创建。重复提交返回同一后继，哪怕后继也已关闭。
- `GET /chat/v1/previous-consultation`：当前轮次客户凭证，不接受 ID 或查询参数，返回同来源、同客户的上一轮只读历史；不存在时 `history:null`。沿用 100 条/128 KiB 响应上限，不是全量历史档案功能。
- 宿主换取新凭证时查询持久化的最新创建轮次。原始第一轮 ID 保持兼容；能力凭证始终固定到签发时的轮次，不因新建会话而迁移。
- Node 成功代理新建后仅清除对应旧能力缓存，下一次换证选取最新轮次。发生网络不确定时可重试；若换证发现轮次变更，前端停止旧请求并要求明确重新载入，不自动提交到新轮次。
- 客户待确认消息继续按会话 ID 存入 sessionStorage。新咨询不复制、不删除旧缓存；查看上一轮时可查看旧待确认内容（不代表已送达），不提供跨轮次重发。
- 原坐席不能凭旧会话授权回复新轮次。新轮次需重新申请人工、接管。旧请求最多在旧轮次幂等确认，不会进入新轮次；机器人上下文仍按 conversation_id 隔离。

存储使用可选 `conversation.Rounds` 端口，内存与 PostgreSQL 均实现。创建时间至少比旧轮次更新时间晚一个微秒以兼容 PostgreSQL 精度；按创建时间/id查询最新，不按消息活跃时间选择。无需数据库迁移。当前查询未新增复合索引或分页，不声称已验证大规模性能。自定义存储未实现该端口时新接口返回 404。

本轮只更新独立 Node 示例接入与共享网关；旧 Go 演示宿主不声明新咨询能力。真实业务宿主需新增严格代理白名单、成功切换后的旧凭证缓存失效，以及 `new_consultation_enabled:true` 的可信能力声明；不要让浏览器决定 customer/source 身份。

## 阅读顺序

1. `internal/webchat/rounds.go`、`rounds_test.go`：创建、幂等、旧凭证隔离与只读历史。
2. `internal/conversation/rounds.go`、`internal/persistence/postgres/rounds.go`：最新轮次查询。
3. `internal/webchat/sessions.go`：换证恢复最新轮次。
4. `integrations/standalone-host/host.mjs`：宿主身份与缓存切换。
5. `web/chat/src/protocol.mjs`、`app.jsx`：明确切换、失败恢复与旧 pending 隔离。

## 2026-10-10 验收结果

[本轮网络、进程和人工复核记录](../examples/archive/integration/standalone-host/2026-10-09T15-23-37-565Z-67fb1a4e/report.json)。目录按启动时 UTC 命名，复核于北京时间次日完成。

实际浏览器完成：第一轮发送、人工接管回复、关闭 → 显式创建第二轮 → 第一轮记录只读查看 → 第二轮重新申请人工、接管、关闭 → 第三轮创建成功回执故意丢失 → 重试发现轮次变化，停止旧请求 → 点击重新载入恢复空白第三轮 → 强制重启网关，登录到期后重新选择同一客户 → 仍恢复第三轮及上一轮记录。

SQL只读核对同一来源/客户恰好三轮：closed/3条消息、closed/2条消息、bot_active/0条消息。第三轮 agent_id 为空；每轮消息总数与不同消息ID数一致。没有第四轮，没有旧内容自动写入第三轮。

第二轮消息成功回执也曾被故意断开；浏览器网络层用相同事件重试，服务返回相同消息和回复ID。因此该次浏览器检查验证了消息去重，但没有制造出持续保留的 pending 界面；pending 按轮次隔离及跨轮次续证拒绝由协议自动测试覆盖，不声称该 UI 分支已人工验收。

自动回归：`go test ./...`、相关 Go 包 race、专用 `standalone_rounds_20261009_test` 库的 PostgreSQL race 集成测试、网页协议27项、Node宿主5项、前端构建、相关包 go vet、git diff --check 均通过。跨网关并发后继测试用共享内存仓库；PostgreSQL新测试验证跨连接池查询与微秒排序，浏览器验证真实持久化恢复，未声称覆盖全部多副本故障。

全程 fake 回复，真实模型调用0；没有修改 CRMEB。界面沿用前端设计技能约束的现有样式和忙/空/失败状态，将旧记录调整为聊天区内可折叠只读面板。验收结束已停止测试进程和专用数据库容器，保留数据卷、新建测试库及证据。
