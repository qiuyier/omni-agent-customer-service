# 通用接入端到端验收

本轮只新增验收工具，不修改客服核心或现有适配器行为。它把真实 HTTP 接入、适配器
进程中断/恢复、模拟渠道交付和人工处置串成可重复运行的断言。
不是生产连接器，不代表任意系统可以不做适配直接接入。

## 运行

在项目根目录执行：

```sh
bash scripts/integration_check.sh
```

脚本使用 `CGO_ENABLED=0` 构建专用二进制，随后运行验收；依赖须已安装或可正常下载。
需要 Linux/macOS、本地监听端口和创建/终止自身子进程的权限，不需要模型密钥、真实渠道
凭证或数据库。不会读取 `.env`，不会接受 Xcode 许可或修改机器配置。

标准输出为 JSON 报告，日志在标准错误。`passed: true` 且退出码为 0 才表示全部通过。
失败断言返回非零并保存已执行场景和失败原因；构建或目录创建等启动失败只输出错误。
每次使用新建的私有临时目录，保留二进制、虚构状态文件和 `run/report.json` 供检查。
报告包含其绝对路径，重复运行不会覆盖旧结果；这些目录不自动清理。

也可手动构建并指定**尚不存在**的结果目录：

```sh
CGO_ENABLED=0 go build -o /tmp/integration-check ./cmd/integration-check
/tmp/integration-check -output-dir /tmp/integration-check-result-new
```

## 实际验证的链路

父进程启动仅绑定 loopback 的真实 Hertz 服务，使用现有路由、Bearer 鉴权、就绪检查、
限流和应用服务；回复生成器替换为固定假回复。每个场景还启动支持交付键去重的本地 HTTP
模拟交付端。客服仓库和交付效果保存在父进程内存中。

子进程使用现有 `integration.HTTPClient`，真实调用接收、回复、交付资格接口，再经 HTTP
调用模拟交付端；不直接调用客服 Service。父进程产生随机测试凭证，经 stdin 传递，
不写入状态或报告；子进程不继承模型密钥和代理环境。工作端点只接受显式 loopback IP，
不跟随重定向、不通过环境代理。

三种中断场景在“服务/渠道已保存、响应尚未返回”处设置确定性等待点。父进程观察到提交
通知后，对自己创建的 worker PID 执行 Kill 并 Wait，确认其退出、状态锁释放，然后启动
另一个 PID 继续处理。不是用 `Close/Open` 冒充进程重启，也不依靠固定睡眠猜测提交时机。
验收父进程对 SIGINT/SIGTERM 进行取消清理，并设置总超时；只终止自身创建的 worker，
不按进程名扫描或终止用户服务。

## 八个场景

| 场景 | 核心断言 |
| --- | --- |
| 接收保存后中断 | 重启重复接收，恢复同一个客户消息 ID，模型只调用一次 |
| 回复保存后中断 | 重启获取同一个已保存回复，不重复生成 |
| 交付保存后中断 | 重启重新检查资格、用原交付键再次调用，只有一个交付效果 |
| 人工确认送达 | 模拟交付已保存但返回 503；按原键核对回执后确认，不再次发送 |
| 人工受限恢复 | 模拟交付未保存并返回 503；核对无回执后授权一次，重启重新检查资格并交付 |
| 人工终止 | 模拟交付已发生但结果不明；终止后重启和重复入站不复活，不撤回已有交付 |
| 恢复前关闭会话 | 授权恢复后通过测试夹具关闭会话；下一进程资格检查拒绝、不调用交付端，再人工终止 |
| 两来源同名外部 ID | 共享 HTTP 后端，两个来源使用同样客户/会话/事件字段，内部命名空间和交付键不同 |

人工场景还验证：查看持久状态、决策/审计跨重开保留、旧版本命令被拒绝、同命令重放不
重复追加审计。这里的操作者是可信验收代码，关闭会话是测试夹具直接做的状态变更，
不是新增了公开人工管理接口或关闭会话接口。

每个场景只有精确校验 HTTP 调用次数、保存的消息标识、对应原键的渠道回执、唯一效果数
和终态后才标记通过。报告的 `worker_pids`、`killed_pid` 记录本次实际进程；PID 不可跨运行
比较。`fake_model_calls` 是假生成器调用次数，不是付费模型调用。

## 没有验证的范围

- 只有适配器子进程中断，客服服务和模拟渠道始终存活；不证明 PostgreSQL/渠道重启持久性、
  断电恢复、多副本故障转移或真实渠道恰好一次交付。
- 测试从归一化 Event 开始，不含真实系统的入站 Webhook、用户认证和外部身份映射。
- 多来源不撞号不等于多租户授权隔离。人工处置入口仍需实际操作端认证、授权及真实证据核查。
- 使用普通 JSON HTTP，未把 SSE、真实模型效果或负载性能混入本次验收。
- 交付资格仍是检查时刻的快照，不能消除检查和实际发送之间的并发窗口。

通过本验收后，可选一个真实系统，只替换其归一化输入和交付适配端，再单独验证以上约束。

## 代码阅读与回归

按 `acceptance.go`（场景与断言）→ `worker.go`（独立进程与真实 HTTP 客户端）→
`fixture.go`（本地服务、故障注入、回执）→ `main.go`（报告与退出码）阅读。

```sh
CGO_ENABLED=0 go test ./cmd/integration-check -count=1 -timeout=90s
go test -race ./cmd/integration-check -count=1 -timeout=90s
```

测试使用 Go 测试二进制的专用 helper 子进程；脚本使用独立构建的真实命令二进制。
两者复用同一组场景断言。其他相关说明：[适配器](integration-adapter.md)、
[交付资格](integration-adapter.md#交付前资格校验)、[人工处置](integration-resolution.md)。
