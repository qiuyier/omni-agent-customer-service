# 无现成客服能力的系统：网页接入最小闭环

这一步提供独立聊天页、宿主身份交换、受限会话接口和一个示例宿主。
没有电商业务逻辑，不依赖 CRMEB 的客服模块，也没有修改 CRMEB。
目前通过专用 `cmd/webchat-demo` 组装；**不会自动改变 `cmd/server` 的路由或配置**。

## 本地体验

在本项目目录执行：

```sh
go run ./cmd/webchat-demo -address 127.0.0.1:8092
```

打开 <http://127.0.0.1:8092>，选择一个演示账号，点击客服入口：

1. 发送问题，查看演示回复。
2. 刷新聊天页，重新获取受限凭证并恢复同一个账号的记录。
3. 返回示例站点，切换另一个账号；其聊天记录独立。
4. 在开发者工具里临时断网，发送后恢复网络，再重试待确认消息。
   重试沿用同一个事件编号和内容；刷新不会自动重发。

该命令只监听字面量回环 IP，不读取部署密钥、连接数据库或调用真实模型。
模拟账号不需要密码，**不是生产登录**。记录保存在内存，浏览器刷新保留，
**停止/重启演示服务会丢失**；不要在演示中输入真实客户资料。
`Ctrl+C` 退出。没有启动 CRMEB、短信、微信、支付或其他外部操作。

页面资源已内嵌到 Go 包，运行演示不需要 Node。修改前端时：

```sh
cd web/chat
npm ci
npm test
npm run build
```

源码在 `web/chat/src`，构建产物在 `internal/webchat/ui/assets`；两者需要一起提交。
运行时无需 CDN、外部字体或前端开发服务器。

## 怎样接入已有系统

宿主网站仍然负责自己的账号和登录。本项目不要求它已有客服功能。

1. 宿主后端从**已验证的登录会话**取出稳定用户 ID，使用单独的宿主密钥，
   服务端调用 `POST /internal/chat/sessions`，请求体只有 `customer_id`。
2. 网关根据密钥确定来源系统，再把来源和用户 ID 映射到固定的客服身份、渠道、
   会话；返回 5 分钟有效的浏览器凭证、到期时间和会话编号。
3. 宿主的 `/host/chat-session` 把受限凭证交给自己的已登录浏览器。
   不能直接把浏览器提交的用户 ID 当成登录身份，也不能把宿主密钥交给浏览器。
4. 同域提供 `/chat/` 页面，只代理 `/chat/v1/messages` 到客服网关。
   私有身份交换路由和现有 `/v1` 管理级业务接口都不能通过这个代理公开。

本次示例实际使用两个 HTTP 监听器，身份交换也经过真实的服务端 HTTP 请求，
不是前端写死用户标识后直连全权限 API。示例宿主是 `cmd/webchat-demo/host.go`，
它只是可阅读的接入样例，不是供生产复制的账号系统。

## 接口与权限

| 接口 | 调用方 | 权限与输入 |
| --- | --- | --- |
| `POST /internal/chat/sessions` | 宿主后端 | 独立宿主 Bearer；`customer_id`；返回 HTTP 201 |
| `POST /host/chat-session` | 已登录浏览器 → 宿主 | HttpOnly 登录 Cookie；空 JSON 对象；不接受客户/来源/会话字段 |
| `GET /chat/v1/messages` | 浏览器 | 短期 Bearer；只读取其绑定会话 |
| `POST /chat/v1/messages` | 浏览器 | 短期 Bearer；只有 `event_id`、`content` |

浏览器 API **不接受任意会话 ID、客户 ID、角色或回复触发 ID**。
每个来源系统、每个用户当前固定一个会话。不同来源/用户重复使用相同事件编号，
也不会碰撞。宿主密钥、浏览器凭证、原有 `/v1` 服务密钥不能互用；部署者仍须
为三者配置不同密钥，网关无法检查其他进程是否错误复用了宿主密钥。

历史结果只允许 `customer`、`bot`、`human_agent`，不返回 system/tool 消息、
内部人员标识或完整领域对象。页面把消息作为纯文本显示，不执行 HTML/Markdown。

发送成功返回存储的 `message_id`，以及：

- `replied`：回复已保存；`reply_message_id` 指向它。
- `waiting_human`：客户消息已保存，但会话处于人工状态；**不表示人工已收到通知**。
- `superseded`：客户消息已保存，当前不再生成这条回复；刷新历史确认当前状态。

接收和生成继续复用现有应用层。网络中断时“是否发送成功”可能未知，
因此浏览器在请求前把待确认的事件编号和原文写进该会话专用的 `sessionStorage`，
重试绝不换编号。只有明确成功的 POST 才清除待确认记录；随后 GET 失败不再重发。
刷新只读历史，恢复待确认记录后由用户选择重试。存储不可用时页面明确阻止发送。
这意味着待确认的**消息原文**可能短暂留在本标签页存储中；凭证不会写进去。

## 安全边界与容量

- 浏览器凭证仅在 JavaScript 内存中；不放 URL、localStorage、sessionStorage 或日志。
  网关只存凭证摘要，默认 TTL 5 分钟，可配置 1 秒至 15 分钟。
- 示例宿主登录 Cookie 为 HttpOnly、SameSite=Strict，30 分钟有效。仅本地 HTTP
  演示不设置 Secure；正式接入必须使用 HTTPS、Secure Cookie 和真实认证。
- 示例宿主校验固定 Host、精确 Origin、请求类型和 JSON 字段；拒绝跨源访问和
  非预期代理路径，不配置通配 CORS。CSP 禁止内联脚本和外部资源。
- 示例宿主将凭证绑定到签发它的登录会话；退出/切换账号会撤销旧登录会话在
  **公共代理处**的后续访问，并在回传上游结果前再次校验。已经接受的发送可能完成，
  退出不是事务回滚。私有网关的凭证本身仍有效至到期，不能公开绕过宿主代理。
- 宿主在服务端内存缓存尚有效的受限凭证，供同一登录会话刷新复用；临近到期才续期。
  这部分缓存不是浏览器持久化，退出或登录会话到期即不可继续使用。
- 网关默认最多 1024 个凭证、1024 个身份、每身份最多 8 个未到期凭证；身份交换
  每宿主每秒 2 次、突发 20 次。每身份读/写共享每秒 2 次、突发 20 次；续期不重置限流。
- 同一会话最多一个进行中的浏览器请求，全局最多 16 个；拒绝时返回 429，不无限排队。
  每个请求最多 20 秒；过期按请求准入时检查，不在已接受请求中途撤销事务。
- 消息最多 4000 个 UTF-8 字节，请求 JSON 最多 32 KiB。历史响应最多最近 100 条可见消息、
  共 128 KiB 文本；单条超过 16 KiB 时带 `content_truncated` 标志。
  当前 Repository 仍加载全量历史，**这不是数据库分页，也不是长期存储容量保障**。

这些限制是单进程的；共享部署、跨副本会话/限流、凭证撤销基础设施、审计、
数据保留政策及生产容量治理都未包含在本步。知识库和模型配置仍沿用原有信任范围，
演示完全关闭知识检索和真实模型，不能把浏览器身份隔离解释为已经完成 SaaS 多租户隔离。

## 实现与阅读顺序

验证命令：

```sh
go test ./...
go test -race ./internal/webchat/... ./cmd/webchat-demo
go vet ./...
npm --prefix web/chat test
```

已完成的浏览器验收：首次登录/空记录、发送及假回复、刷新恢复、跨标签页切换账号、
HTML 样式消息按纯文本显示，以及 390 px 和 1280 px 布局检查。
故障/过期重试、宿主代理越权、内部消息过滤、容量与并发边界由自动化测试覆盖；
本次没有对真实业务系统、生产登录或真实模型做验收。

1. `internal/webchat/gateway.go`：独立入口、依赖和路由权限范围。
2. `internal/webchat/sessions.go`：宿主身份、稳定映射、短期凭证、容量与限流。
3. `internal/webchat/messages.go`：可见历史、消息接收、幂等回复恢复。
4. `cmd/webchat-demo/host.go`：已有系统需要提供的登录桥接和同域代理。
5. `web/chat/src/protocol.mjs`、`web/chat/src/app.jsx`：续期、待确认消息、页面状态。
6. `internal/webchat/gateway_test.go`、`cmd/webchat-demo/*_test.go`：越权、重放与宿主安全验证。

本步没有订单/退款适配器、CRMEB 插件、跨域 iframe/SSO、流式 UI、多个会话的列表管理、
人工工作台或通知系统。实际接入一个业务系统时，先替换示例身份桥接，再选择持久化和
部署方式；行业知识与业务工具仍通过独立配置/适配层提供，不能写进通用会话内核。
