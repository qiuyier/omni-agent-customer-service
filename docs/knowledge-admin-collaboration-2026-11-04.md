# 知识管理：双浏览器协作验收

日期：2026-11-04（Asia/Shanghai）。结果：以下实测场景通过，未发现需要修复的业务功能问题。

## 环境与边界

使用 `OMNI_ADMIN_UI_LAB=1 go test -tags browserlab ./internal/knowledge/adminauth -run '^TestBrowserLab$' -v -count=1 -timeout=30m` 启动现有纯内存夹具；真实管理页面、认证与管理 HTTP，独立内置浏览器和 Microsoft Edge 会话。账号为发布管理员 admin 与编辑管理员 editor，后者没有发布权限，不声称两个账号都有发布权限。

仅使用虚构 FAQ，无数据库、真实模型、CRMEB/PHP74 或生产配置；没有改动业务代码。不同浏览器使用同一入口与同一知识状态，而非两套数据。

## 实测步骤与结果

1. 两个账号同时读取 r0。admin 保存 `collab` 条目产生 r1；editor 保持旧 r0，本地输入不同答案后保存。
2. editor 页面显示“其他管理员已更新”，保留本地答案，保存和编辑控件暂停。核对服务器后显示 r1 与 admin 操作记录，不自动覆盖本地内容。
3. editor 明确确认采用服务器草稿，恢复可编辑状态；修改答案并保存成功，产生 r2，操作记录归属于 editor。
4. admin 页面仍为 r1，点击发布并确认后被冲突保护拦截，发布控件暂停。核对显示服务器仍为 r2、尚未发布，没有误发布旧草稿。明确采用 r2 后恢复正常工作区。
5. admin 载入一条虚构回归用例并运行，草稿通过 1 条，报告显示 r2（尚无发布版本，发布侧不可比较）。退出后只显示登录页。
6. 在同一内置浏览器改登录 editor，原用例、批量报告和下载报告入口均不再显示，页面加载服务器 r2。发布区域明确显示无发布权限。
7. 修改本地答案但不保存，退出再登录 admin，答案仍为服务器 r2 内容，未保存文本没有跨账号保留。两个测试会话最终均退出，临时页面关闭。

Edge 首次输入中文时原生输入没有完整写入，服务器拒绝了无效 FAQ；改用粘贴填入完整字段后才执行有效冲突验收。这是操作输入问题，不记作应用缺陷。

## 证据范围

本轮是浏览器手工操作验收，不是自动化断言计数；未重新验证数据库持久化、真实模型效果，也未覆盖请求在途切号或所有同浏览器跨标签页竞态。此前的 [完整链路验收](managed-knowledge-e2e.md) 保留其独立证据范围。本轮不新增产品功能、不提交、不发布。
