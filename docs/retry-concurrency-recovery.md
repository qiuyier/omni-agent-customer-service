# 回复重试与人工生命周期竞态（2026-10-23）

## 结论与修复

新增定序回归未发现服务端重复生成、重复客户消息或人工接管后迟到机器人回复落库。发现并修复前端状态同步缺口：自动轮询原先只刷新历史，不重新核验待重试事件，旧入口可能一直保留。

- 空闲页面轮询历史后，对原待确认事件进行只读回执查询。已有回复、转人工、关闭或问题被替代时，清理当前事件的本地恢复入口。
- 正常可见页面按既有约 5 秒轮询周期更新，不承诺瞬时撤除；隐藏、离线及失败退避沿用原策略。
- 本地发送进行中不执行这次清理。操作版本、会话和取消信号共同阻止旧轮询结果覆盖新操作。
- 核验失败或无效回执撤销旧的重试资格，但保留原事件。不自动发送、不自动生成。
- 并发请求返回 busy 后，回执核验不再立即把忙碌原因覆盖为普通失败提示。后续轮询仍按服务端当前状态更新；回执不是“生成请求已结束”的证明。

## 验收

- 网关定序测试连续 3 遍：先失败、回执允许后才转人工；重试生成期间等待人工/接管/关闭；两个会话令牌同时重试同一个失败事件。
- 双客户端成功场景：第二请求 429；释放第一请求后，只有 1 条客户消息及 1 条关联回复；再次重放不新增模型调用。总调用为首次失败 1 次、手动重试 1 次。
- PostgreSQL：专用临时 retry_race_test 数据库，waiting/active/closed 各重复 3 遍。包含首次失败、允许回执、重试、另一客户端同事件 429、人工流转、迟到结果抑制、重建 HTTP 网关与数据库连接后回执/历史/重放验证。
- go test -race -count=1 ./internal/webchat ./internal/customerservice 通过。
- 网页及相关接入测试 139 项通过，包含轮询撤除和失效轮询不能修改恢复状态。
- 四个通用前端 JavaScript 产物重建成功。

本轮未运行真实浏览器双标签页操作，也未调用外部模型。双客户端由同一用户的两个会话令牌模拟，不能据此声称已验收浏览器标签页切换、视觉呈现或多网关实例并发。数据库“重启”是网关与连接池重建，不是 PostgreSQL 容器重启。

## 范围

这是通用客服能力，无 CRMEB 业务硬编码；没有修改外部 CRMEB、共享 PHP74、已有测试数据库或上线发布。专用临时容器清理后，其 tmpfs 虚构测试数据不可恢复；既有 standalone 持久卷保留。
