# 通用接入适配器：最小可恢复闭环

本轮新增 `internal/integration`，不修改客服 HTTP 协议、数据库、鉴权或模型行为。
它接收中性的会话、客户、渠道、事件和文本，不包含订单、退款等行业规则。
这是仓库内部可复用原型，不是公开 Go SDK，也不代表任意系统已经完成接入。
协议依据见[通用接入契约](integration-contract.md)。

## 离线运行

```sh
go run ./cmd/integration-demo
go test -race ./internal/integration -count=1
```

示例使用实际应用服务、内存仓库、固定假回复和支持幂等的模拟交付端，不读取
`.env`、不联网、不调用付费模型。两个来源使用完全相同的外部 ID；来源 A 分别
丢失一次接收确认、回复确认和交付确认。每一步关闭并重新打开适配器，最终输出
两个 `completed`、两次假模型调用、两条唯一交付、三次确认丢失恢复。
输出包含新建的私有临时状态目录，保留供检查，包含的都是虚构数据。
这只模拟适配器重开，后台服务和交付端始终存活，不是断电或整个分布式系统重启测试。

## 接入方式

1. 从可信启动配置确定 `SourceID`、`DestinationID` 和独立 `Directory`。
   来源 ID 不能由终端用户任意指定。各来源使用不同目录，恢复时保持原来的来源、
   交付目标以及同一个持久化客服后端，不能把旧状态指向全新数据库。
2. 使用 `NewHTTPClient(HTTPConfig{BaseURL: ..., BearerToken: ...})` 连接现有客服
   REST API，或实现 `Client`。默认要求 HTTPS；本地测试 HTTP 必须显式开启
   `AllowInsecureHTTP`。不会跟随重定向，不读取环境代理。
3. 实现 `Deliverer.Deliver(ctx, Delivery)`：把完整回复发送到实际渠道，并按
   `Delivery.Key` 持久化去重。同键不同内容应返回不可重试冲突。连接配置和凭证
   由可信代码装配，不能从客户文本取地址。端口必须遵守 context 取消/超时。
4. `Open(config, client, deliverer)` 后调用 `Accept(ctx, Event)`，成功才确认入站
   事件已被适配器保存。相同键、相同事件返回原记录；不同内容返回 `ErrConflict`。
5. 调用方通过 `List` 找到未完成记录，按照 `NextAttemptAt` 调度 `Advance`。
   一次最多进行一个外部操作，没有后台轮询、Webhook 入口或自动启动的工作进程。
6. 停止时 `Close`；重开同一目录继续处理。HTTP 客户端另行 `Close`。

外部会话、客户、渠道和事件 ID 使用版本化 JSON 元组的 SHA-256 稳定映射，
含来源命名空间；出站仍携带原始外部会话/客户 ID。映射用于避免命名冲突，
不是身份认证、授权或多租户数据隔离。

## 恢复规则

`pending_receive → pending_reply → pending_delivery → completed`

- 调用前先保存尝试次数，成功后保存下一阶段；确认丢失仍使用原 ID 和交付键。
- 接收去重返回 `next_action=none` 不等于回复已生成。记录有自动回复意图且仍为
  bot 状态时，继续显式请求回复，利用现有服务的回复幂等。
- 每阶段默认最多 3 次尝试、90 秒超时、1 秒重试间隔；配置最多 10 次、5 分钟
  超时、1 小时间隔。429/部分 5xx、传输错误可有限重试；409/412 等不可盲目重试。
  已耗尽次数、无效响应、人工状态或超过支持范围的 Retry-After 进入 `needs_attention`。
- `ErrNotReady` 表示尚未到重试时间，`ErrAttemptFailed` 表示本次失败但保留重试。
  `ErrNeedsAttention` 需要人工调查。本版本没有人工恢复/跳过/重置接口，不要通过
  删除记录、更换事件 ID 或重复入站来规避停止状态。
- 保存失败返回 `ErrStore` 并停止该实例的后续调用；排除存储故障后关闭重开，
  从实际落盘阶段恢复。即使保存结果不确定也不会立即重新交付。
- 交付端只有在真实交付已被可靠确认时才返回 nil。没有交付端持久化幂等，就不能
  承诺端到端“恰好一次”；未知错误的有限重试仍可能再次调用交付端。

回复重放可能返回历史内容，不授予当前发送权限。实际 Deliverer 还必须检查渠道
权限、当前会话归属及过期回复策略；原型没有自动检查交付时最新状态，也不保证多条
入站消息按序推进。不满足发送条件时应停止并转人工审查，而不是直接发送历史回复。

## 存储与生产边界

- Linux/macOS 本地文件系统、单活实例；目录生命周期文件锁阻止同时打开。不支持的
  平台直接拒绝。不是共享网络盘队列、分布式任务系统或多副本故障转移方案。
- 私有目录权限 0700、文件 0600，JSON 临时文件同步、原子替换并同步目录。
  已存在且过宽的权限直接拒绝，不自动更改用户目录。配置路径及上级目录需可信。
- 状态以明文包含客户输入和回复，须纳入敏感数据存储、备份和保留策略。凭证、原始
  外部错误正文不写入状态；固定错误码用于分类。文件不是防恶意篡改的安全边界。
- 最多 128 条记录，输入 16 KiB、回复 64 KiB；完成和待处理记录都保留用于去重。
  满容量返回 `ErrFull`，不自动清理、压缩或重置。硬崩溃可能留下私有临时文件。
- 重试预算在调用前持久化，崩溃也消耗一次预算；调用后最后一次确认丢失可能需要人工
  核对。不能以原型测试代替生产持久性、容量、权限和真实渠道故障验收。

进入生产前仍需选择实际业务系统、实现其入站认证和交付端、持久化幂等与交付资格检查，
再按容量需要替换本地状态存储。通用性来自稳定的核心协议与可替换端口，不是免适配接入。
