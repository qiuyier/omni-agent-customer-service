2026-10-26。本轮收口的候选范围，不是发布公告或生产开放批准。目标是通用文本客服；CRMEB 只是业务适配示例，不是运行依赖。

## 交付什么

以**源码、锁定依赖、构建步骤、通用接入契约及本机参考部署**为最小交付形态。部署方按目标环境构建二进制；本轮不承诺预编译多平台安装包、托管 SaaS、一键公网安装或零适配接入。

| 纳入基线 | 边界 |
| --- | --- |
| 客户聊天与坐席工作台 | 沿用业务系统已验证身份；没有原客服模块也可接入，但须提供身份验证和员工授权 |
| 人工接待闭环 | 申请、接管、回复、结束、新咨询；不承诺自动排班、工单或电话回访 |
| PostgreSQL 消息和会话持久化 | 稳定来源/用户映射、回执和历史恢复；进程重启不等于备份恢复 |
| 单业务独立实例 AI | 显式启用模型及 keyword FAQ；默认 fake，失败不降级假回复；资料和模型由部署方选择并验收 |
| 通用业务适配 | Node host-kit 可复用；PHP/Java 按同一契约实现，不要求改用 CRMEB |
| 多业务共享实例 | 仅 fake/人工；AI/知识隔离需求使用独立实例，多宿主 AI 不在承诺内 |
| 配置、资源预检和迁移入口 | 预检不是模型质量验证；迁移须确认专用库，生产运维由部署方负责 |

现有早期 `/v1` API、语义检索、回答依据校验和多意图实验不因存在于源码就自动成为本轮 WebChat 推荐交付路径；保留原有文档和限制，不删除旧能力，也不据此扩大 1.0.0 验收承诺。没有订单、退款、预约等业务执行工具，不保证任意模型准确率。

## 环境与平台口径

- 构建要求依据 go.mod：Go 1.25.0；固定部署文档使用 Node.js 24、Docker Compose、PostgreSQL 16，具体镜像以 compose.yaml 为准。
- 当前端到端证据来自本机 macOS + Docker Desktop。Linux 是源码部署目标，但未获得候选版本实际运行证据前，不宣称 Linux 已验收；Windows 原生不纳入本轮支持承诺。
- 参考页面已有构建产物，可按文档启动；修改页面时按前端锁文件安装并构建相应页面，不能用仅构建 demo 的命令替代业务页面构建。
- 网关与参考宿主默认回环监听。参考演示认证、HTTP Cookie 和内存登录不能用于公网真实客户。

## 使用入口和责任

唯一新手入口为 [最小使用指南](minimal-use.md)：先跑固定持久化参考部署，再替换业务身份适配，最后按需启用 AI。具体协议见 [系统接入职责](system-integration.md)，目标系统交接见 [接入交付指南](integration-delivery.md)。

项目负责网关、页面、适配契约与参考示例；业务方负责登录、退出、禁用、稳定身份和坐席授权；部署方负责专用数据库、密钥、HTTPS、网络、备份、进程托管和值守。没有现成客服模块不妨碍接入，没有可信身份与授权则不能直接开放。
