# 客户与坐席自动更新

通用网页客服能力，不依赖 CRMEB。客户自动读取当前咨询的新消息和状态，坐席自动读取队列及选中会话的历史。保留手动刷新；采用轮询，不是实时推送或送达时限承诺。

## 行为与安全边界

- 一次读取结束后约5秒再读；每个轮询器只保留一个在途读取，不补发积压的定时任务。
- 页面隐藏时取消定时任务并中止当前读取；重新可见时恢复。发送、接管、关闭、切换等前台操作会使旧后台结果作废。已被服务端接受的请求不保证能撤销。
- 失败后按10、20、40、60秒退避，最长60秒，成功后回到5秒；页面显示暂停或重试提示。手动操作/重新激活会重新建立调度。
- 后台更新不修改草稿，不清理/重发待确认消息，不自动接管、回复、关闭或创建下一轮。坐席历史接口虽然使用 POST，但 action 固定为 history。
- 客户读取前核对宿主身份，能力续期固定到原轮次；账号/轮次变化要求重新载入，不能把旧请求自动发送到新身份。清除能力后旧401也不能重新恢复旧能力。
- 坐席在读取队列和历史前后复核身份；变更时丢弃快照、清除旧选择，待确认缓存仍留在原坐席/会话命名空间。页面操作版本和取消信号共同阻止迟到快照覆盖新的选择。
- 同身份刷新保留坐席选择和草稿。切换身份/轮次仍清空页面草稿；未发送草稿不提供跨轮次自动迁移。

这不是生产推送服务：没有新增 WebSocket/SSE、消息分页、服务端增量游标、分布式能力存储或负载验收。历史接口仍沿用原读取方式，规模化接入前应单独评估轮询成本和限流。浏览器实际可见性/计时器调度由运行环境决定。

## 2026-10-11 验收

[本轮证据](../examples/archive/integration/standalone-host/2026-10-11T14-01-23-866Z-2c3f96c0/report.json)。之前 2026-10-10 启动的浏览器验收中断，未将其标为通过；本轮重新启动独立来源完成验收。

真实浏览器 + 专用 PostgreSQL + 模拟回复：

1. 坐席先登录，客户申请人工后队列自动出现新咨询。
2. 坐席接管，客户自动显示“人工正在处理”。
3. 坐席先填写草稿；客户发送消息后，坐席自动收到，草稿仍保留。
4. 客户先填写草稿；坐席发送回复后，客户自动收到，草稿仍保留。
5. 坐席关闭，客户自动禁发并出现“发起新咨询”。
6. 显式新建后，新轮次为空白，没有原消息和草稿；最终构建重新加载正常。

上述过程没有点击“刷新记录”或“刷新队列”。网络记录中客户发送、坐席回复、接管、关闭、新建各1次，其余反复请求为身份/队列/历史读取；没有自动写请求，真实模型调用0。

自动测试：网页协议/调度共36项通过，宿主5项通过，网页网关及嵌入资源 Go 测试通过，前端构建与 git diff --check 通过。隐藏/恢复、失败退避、慢请求不重叠、销毁/切换后迟到响应、读取途中坐席切换由确定性单元测试覆盖；不宣称所有浏览器隐藏策略或真实断网时序都经过人工验收。

使用前端设计技能沿用现有样式，新增低干扰更新状态提示，没有新增依赖。测试服务、临时浏览器标签页及专用数据库容器均在验收后关闭；数据卷与证据保留。没有修改 CRMEB，没有提交或推送 Git。
