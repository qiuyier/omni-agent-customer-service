1. 用旧版迁移建立 schema 2，通过旧网关真实 HTTP 创建 bot_active、waiting_human、human_active 三个虚构客户会话，发送客户/固定/人工回复并写入两个坐席已读记录。不是用新程序或手工 INSERT 拼装旧数据。

3. 再次执行新版 migrate，旧数据仍完全不变。
4. 旧版网关的资源预检对 schema 3 返回失败，证实不能直接回退旧程序。
5. 新网关重新签发同一客户凭据，获得相同会话 ID；完整消息历史、原事件回执与升级前一致，读取未修改旧表。
6. 原机器人会话可继续固定回复，原等待会话可接管并人工回复，原已接管会话可继续回复并关闭。
7. 在同一升级后的库启动真实管理进程，经管理员登录保存 FAQ 并发布到 revision 2。
8. 停止网关及管理进程、真实重启 PostgreSQL 容器，重新解析动态宿主端口后启动。三个旧表与重启前的操作后快照完全相等；管理完整 state 相等，旧 Cookie 401，重新登录成功。未关闭会话通过 HTTP 再次核对完整历史；已关闭会话通过完整数据库行比较，不声称重签凭据后仍绑定旧会话。
