# 通用业务系统接入：配置与启动检查

可选[人工接管模块](human-handoff.md)现已提供本地最小闭环；真实员工认证、通知及新咨询轮次不包含在内。未显式配置时保持原无人工接口模式。

已完成[资源预检验收](host-onboarding-acceptance.md)：真实独立PostgreSQL检查及回归通过，模型/embedding请求数为0。

适用于没有客服模块的已有业务系统，不依赖CRMEB或电商接口。复用私有网关 cmd/webchat-server、既有会话接口和聊天页；不再使用测试启动器作为正式接入入口。

## 1. 先分清责任与配置

[网关配置模板](../deploy/webchat-server.env.example)故意留空身份、密钥和数据库，不能原样启动。程序不自动加载 .env；由进程管理器或密钥管理器注入，切勿提交填入密钥的文件、把密钥放进命令行参数或浏览器。

| 配置 | 提供方与约束 |
| --- | --- |
| WEBCHAT_HOST_ID | 接入方确定的稳定系统标识，不能用保留演示名称；变更会影响身份映射 |
| WEBCHAT_HOST_SECRET | 双方服务端共享的独立随机凭证，32—128字节、无空白、不能是chat_浏览器凭证；不得放进前端 |
| DATABASE_URL | 客服专用PostgreSQL连接，不能误指业务生产库；先由运维显式迁移，不自动建表或回退内存 |
| WEBCHAT_ADDRESS | 字面量回环IP与端口，默认127.0.0.1:8093；此入口不支持绑定公网或任意容器网络地址 |
| WEBCHAT_REPLY_MODE | 默认fake；必须显式设置ai才读取模型/知识配置，不因存在密钥就启用AI |
| AI_PROVIDER / PROTOCOL / MODEL / BASE_URL / API_KEY | 模型由接入方选择，密钥只给网关；Base URL为API根地址，不是完整聊天接口；默认要求非回环端点HTTPS |
| KNOWLEDGE_FAQ_PATH | 可选；相对网关工作目录解析；必须是最大1 MiB的UTF-8严格FAQ数组；空值禁用、[]为空知识快照 |
| KNOWLEDGE_RETRIEVER | 默认keyword，无embedding调用；semantic需显式配置并可能在正式启动时产生embedding费用 |
| 业务后端的模式元数据 | /host/me和/host/chat-session返回可信storage=postgres、reply_mode，与网关配置保持一致；不是模型可用性探针 |

当前网关是一实例一套宿主配置、模型和知识。双账号会话隔离不等于共享实例的多租户知识隔离。不同系统如需配置/知识隔离，先按独立实例规划；不能自行认为当前已支持任意多租户共用。

## 2. 分层检查，再启动

以下命令从仓库根目录运行，假设所需环境已安全注入。不读取或展示根目录已有模型密钥，不自动请求模型。

```sh
go run ./cmd/webchat-server -check-config
go run ./cmd/webchat-server -check-resources
go run ./cmd/webchat-server
```

| 阶段 | 做什么 | 不代表什么 |
| --- | --- | --- |
| -check-config | 配置格式、身份/密钥规则、地址和预算是否合法 | 不读FAQ、不连数据库、不验证模型 |
| -check-resources | 同样校验配置；ai时读取并严格解析本地FAQ；连接PostgreSQL并检查表结构，结束后关闭连接 | 不监听、不迁移、不创建消息、不调用模型/embedding，不验证索引、模型凭据/质量、端口占用或业务登录 |
| 正式启动 | 执行现有数据库检查、知识初始化并监听；配置/资源错误立即失败，无fake或内存降级 | semantic可能调用embedding；AI回答通常在用户发消息时生成；仍须业务侧端到端验收 |

两个检查参数不能同时使用。成功退出码0，失败非0；诊断不输出DSN、密钥、FAQ内容或底层供应商报错。fake模式有意忽略AI与知识变量，即使FAQ路径无效也不检查；要检查AI资源须显式设置ai。

数据库预检沿用10秒初始化预算。知识预检沿用现有严格解析器，接受空数组；不会构建semantic索引。失败时按提示检查环境配置、文件格式或连通性/迁移，修正后重跑；不要通过切换fake掩盖AI配置错误。

若提示缺表，由数据库负责人确认连接目标后单独运行 cmd/migrate；预检本身从不迁移。检查只代表该时点状态，之后文件/数据库变化仍可能导致启动失败。生产数据库权限、备份、网络与TLS仍由部署方管理。

## 3. 业务系统的最小实现清单

- [ ] 保留自己的真实登录/退出，从服务端会话读取稳定用户ID，绝不信任客户端自报customer_id。
- [ ] 服务端用独立宿主凭证调用私有POST /internal/chat/sessions，提交customer_id；不公开这个路径或宿主密钥。
- [ ] GET /host/me提供当前认证用户与可信模式；POST /host/chat-session绑定当前登录，换取短期、受限会话凭证。
- [ ] 同域挂载聊天页及资源，仅精确代理GET/POST /chat/v1/messages；限制请求体和字段，校验Cookie、Origin及凭证归属。
- [ ] 退出或切账号撤销宿主登录/凭证绑定，迟到响应不得泄漏旧账号历史；不能靠前端隐藏消息实现隔离。
- [ ] POST仅接收event_id/content；失败重试保持原ID与内容，不自动创建新事件、不声称供应商调用恰好一次。
- [ ] AI等待预算保持从内到外递增：网关110秒、私有HTTP写入115秒、业务代理120秒、公共服务响应预算至少125秒、浏览器150秒；身份/历史读取可保持较短预算。按实际反向代理核对。
- [ ] 未登录、跨账号、刷新、重登、模型失败、响应丢失均完成验收；确认无密钥进入URL、浏览器存储或日志。

接口字段、安全责任与凭证生命周期以[网页接入契约](browser-chat.md)为准，Node实现参见[独立业务样例](../integrations/standalone-host/README.md)。其中模拟账号选择、回环HTTP Cookie和故障代理仅供本地演示，不能直接上线；生产需要真实认证、HTTPS/Secure Cookie、会话存储和网络边界。网关当前只监听回环，跨容器/跨主机部署需另行设计受保护的网络接入，不可直接改成公网监听。

## 4. 完成标准与当前边界

接入完成至少要求：两层预检通过；业务登录→身份交换→发送→持久化历史跑通；账号隔离与重试通过；如启用AI，经授权完成少量真实模型问答验收。预检不会自动发起付费探测，真实调用需另外安排。

未实现的业务查询/执行、人工坐席/工单、多租户知识隔离，不能仅靠FAQ或模式标记宣称已经具备。[真实AI验收记录](../integrations/standalone-host/ai-acceptance.md)证明的是已测试链路，不是所有系统开箱即用或生产认证。
