16 条 FAQ 与 30 道题全部是助手编写的虚构材料；结果只用于开发，不代表真实商家服务质量。

本轮没有漏掉预期引用，但保留题的一道改地址问题把发货条目排在改址条目前；
7 道题包含额外引用，导致总体集合匹配为23/30。不是“程序报错”，也不是回答质量分数。
开发题与知识条目由同一助手编写，很多题直接使用资料关键词，分数偏乐观是可预期的；
保留题虽然独立存放，仍是同源合成题，不能当作独立真实用户分布。

## 保留的失败，不按结果补关键词或改标签

| 题目 | 现象 |
| --- | --- |
| dev_freight | “包裹”同时触发物流条目，运费题混入物流资料。 |
| dev_cup_care | 商品名称同时触发规格资料，但问题只问清洗。 |
| dev_negation | “不用讲发票”仍触发发票关键词，忽略了否定。 |
| hold_freight_edge | 包裹、用券带入物流和优惠券规则，题目实际只问运费边界。 |
| hold_shipped_address | 已发货状态触发发货规则且排在改址之前，问题焦点是改地址能力。 |
| hold_used_return | 提及退款使退款阶段条目混入，但题目问的是退货条件是否适用。 |
| hold_stock | 杯子规格因商品名命中，但不能支持实时库存数量。 |

这些标签按“能支持题目中的事实、条件或操作指引”判断相关性，不把同店/同商品
自动判为相关。标签本身也需要业务审阅；若未来改用更宽的相关性定义，应明确升级
标签版本后重跑，不能把不同标准的成绩直接比较。
库存条目即使带“没有实时库存”的声明，也不提供库存事实或库存查询入口；
本集将仅靠产品名称命中的规格片段视为无效库存证据，而不是让模型据此编数量。
