### 回答内容审阅（助手逐条检查，非用户签收）

- **改密，两种模式**：符合资料中的登录页、注册邮箱验证和设置密码步骤；没有索取密码/验证码，
  没有声称已经修改。普通回复附带的是虚构资料 source，不是已验证的公开链接。
- **节假日，两种模式**：正确区分常规工作日时间与节假日公告，没有编造具体节假日排班。
  流式回复末尾建议补充日期，但当前静态 FAQ 不会因此自动获得新的排班资料。
- **库存，两种模式**：明确表示无法确认库存，未编造有货/售罄或数量。
  **质量待改进**：普通回复称“我可以更准确地为您核实”，流式回复称“我会尽力为您核实”，
  暗示当前服务具备库存核实能力；事实上没有接入库存查询工具。
  流式回复还主动索取订单号，对当前无查询能力的场景没有明确必要性。

结论：真实 HTTP/SSE 与顺序重放机制通过，小样例核心事实约束满足；
回答质量不能无条件标记全通过，建议收紧无资料时的能力承诺和不必要信息收集，
再做有针对性的回归。此轮只记录问题，没有自动修改 Prompt、业务代码或样例标签。
原始 JSON 的 `manual_review_required` 保持原样；仍需业务负责人确认措辞与验收标准。

本轮不覆盖生产数据库、并发重复请求、真实浏览器、负载测试、真实业务准确率或账单统计。

## 工具覆盖与人工判断

样例为 [reply_cases.json](reply_cases.json)，使用现有的 3 条虚构 FAQ：

- 有明确资料：忘记密码，应说明验证和重设步骤，不声称已执行改密。
- 无相关资料：实时库存，应说明无法确认，不编造库存状态。
- 资料相关但不充分：节假日人工排班，不把工作日时间当作节假日安排。

每条分别创建普通回复和 SSE 的独立会话；首次完成后，分别用原模式和另一模式
重试同一个 Trigger，检查返回同一回复、不再次检索/调用模型、存储仍为一客一机。
默认共 6 次首次生成和 12 次完成后重放。这里验证的是顺序重放，不是并发重复请求
下的“模型只调用一次”，也不覆盖数据库、现有服务器或浏览器客户端。

自动检查还包括 HTTP 状态、消息与 Trigger 对应关系、传给回复生成器的引用集合、
SSE delta 拼接与 completed 内容一致、单一终止事件及模型完成/清理状态。
引用记录位于应用层接口，不是供应商 HTTP 抓包，也不能证明模型理解或使用了资料。

## 复现

先在本地安全加载回复模型 `AI_*` / 厂商凭据和独立的 `EMBEDDING_*` 配置；
程序不自动读取 `.env.local`。不要把密钥粘贴进报告或命令参数。
以下命令会发送 FAQ、问题和检索资料到已配置服务，可能产生费用：

~~~bash
go run ./cmd/reply-check -allow-model-api -allow-embedding-api -timeout 10m
~~~

两个许可参数缺一不可；FAQ 和标签在联网前校验。默认使用
`examples/knowledge/faq.json` 和 `examples/knowledge/reply_cases.json`，
可用 `-faq` / `-cases` 覆盖；每轮允许 1～10 条用例。
命令固定使用语义检索，不受 `KNOWLEDGE_RETRIEVER=keyword` 影响；
其余 Embedding 配置、阈值和查询超时仍由环境决定。
整体超时默认 10 分钟、最多 30 分钟，包含建索引；单次生成预算为 75 秒。

命令临时监听 `127.0.0.1` 的随机端口，使用一次性鉴权令牌与内存仓库，
无需启动 `cmd/server` 或数据库，也不会修改已有会话。stdout 为 JSON，
stderr 为进度与安全错误。进入验收循环后发生失败会输出明确的部分报告并退出 1；
配置、输入或索引初始化失败则直接报错，不生成已执行用例报告。
若客户端取消或超时先于服务清理结束，失败报告的诊断快照可能尚不完整；缺失的
终止数据不能解读成清理成功，机械验收仍会失败。

报告不写凭据、endpoint、业务空间 ID 或供应商原始错误；但包含问题、模型回复、
引用 ID 与模型名，并不是可直接公开的脱敏日志。自定义数据应事先获得授权。
