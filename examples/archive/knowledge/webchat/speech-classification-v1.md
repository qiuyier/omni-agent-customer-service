# 独立言语行为分类验证 v1（2026-09-23）

## 结论与范围

十二条跨行业配对样例，本次单轮十二次请求全部与逐段分类标注一致，零格式错误。
这支持继续验证“先分类、再核对事实”的设计，但不证明原有 v5 事实审查问题已修复。
本轮没有把分类器接入 v5，也没有重跑完整事实审查语料；没有修改 CRMEB 或正式客服回复链路。
分类正确不等于有依据：无依据的能力与有依据的能力都应归为 assertion，后续仍需要证据核对。

## 为什么单独验证

上一轮图书馆正例把“无法确认按钮存在”当成缺失事实；设备回答又把真实操作步骤放进通用建议。
因此本轮不增加领域关键词或放宽证据规则，而是独立输出 quote、act、reason，
将否定系统事实、未知、助手自身限制、更正、求证和安全/礼貌说明分开计分。

| 边界 | 样例数 | 本次结果 |
| --- | --- | --- |
| 图书馆：未知、否定系统能力、更正与求证混合 | 3 | 全部逐段匹配 |
| 报名：一般求证、无依据功能、有依据的同一功能 | 3 | 全部逐段匹配 |
| 账号：助手不能代办、混合句中的功能/步骤/安全提醒 | 2 | 全部逐段匹配 |
| 维修：先确认、条件使用、否定系统能力、更正后新增否定断言 | 4 | 全部逐段匹配 |

人工核对所有返回段落：

- “系统没有一键续借按钮”被归为 assertion，未因否定词免审。
- “无法确认是否有一键续借按钮”被归为 uncertainty。
- 相同门户查询建议，无论 reference 是否提供依据都归为 assertion，没有混入事实正确性评分。
- “我无法代您查询”与“您可以通过账号安全功能查看”分别归为 self_limitation 与 assertion。
- 有依据的重置密码步骤仍归为 assertion，没有被放进通用建议。
- “之前说支持没有依据”与随后新增的“不支持”断言正确拆分。

## 冻结与证据

样例和预期标签在首次调用前写入并通过离线校验；模型只能看到 reference、history、answer，
看不到样例 ID、预期类别或标注理由。使用 GLM `glm-5.3-flash`、`reasoning_effort=low`。
预算十二次请求，实际十二次，无重试、无复核调用。运行后核对三个源码文件哈希与冻结记录一致。

- [固定样例](../../../regression/knowledge/webchat/speech_classification_cases.json)
- [冻结记录](eval_runs/2026-09-23/speech-v1/freeze.json)
- [原始输出与完整标签](eval_runs/2026-09-23/speech-v1/results.json)
- [进度](eval_runs/2026-09-23/speech-v1/progress.txt)及[退出记录](eval_runs/2026-09-23/speech-v1/exit.json)

评分允许同类片段作不同切分，但每个文字/数字必须覆盖且类别一致；同一文字标签冲突为错误。
本地严格拒绝 unknown fields、非法类别、非原文引用、漏段，防止非法结构被算作匹配。
这是本地严格解析，不是供应商强制 JSON Schema 生成。本次输出合规不代表将来必然合规。

## 限制与下一步

这十二题由开发者/助手标注，属于本轮开发样例，不是第三方盲测，也没有重复采样估计稳定率。
本轮包含混合句，但没有覆盖上一轮两条完整长回答的全部标题、过渡语和上下文。
当前按原文匹配全部重复片段，不支持同一原文不同出现位置需要不同类别的复杂歧义。

下一步应先把原有失败长回答和新增保留样例纳入分类回归；只有验证分类可靠后，
才在独立实验里连接事实审查，并跑原十二题加八条保留题的完整验收。
连接时仍须让复核看到原始全文，不能仅因分类为 advice/uncertainty 就永久免审；
不能把本次十二条 matched 换算成十二条事实正确或宣称已达到上线条件。
