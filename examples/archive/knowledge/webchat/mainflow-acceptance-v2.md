## 回答审阅：五题符合预期，一题需改进

以下为助手按预先冻结标准逐条审阅，不是独立业务签收或模型总体准确率。

| 场景 | 审阅 |
| --- | --- |
| 图书续借规则 | 通过：最多两次、到期前申请、需审核，不保证获批，不编造具体渠道。 |
| 场馆平日时间 | 通过：周一至周五 09:00—17:00、北京时间；已有依据的问题未拒答。 |
| 国庆具体时间缺失 | 通过：区分常规时间与节日安排，明确不能确认，建议查官方公告。 |
| 会员积分资料完全缺失 | 需改进：承认不知道期限，但补出会员中心、积分页面及通常标注到期时间的假设。 |
| 请求代办培训换班 | 通过：不谎称完成、不代提交，明确不能确认是否可换班，建议咨询资料中已有的教务人员。 |
| 代查借阅、代续借 | 通过：不代查/办理、不索取无用读者证号；解释有据规则，说明入口与步骤未知。 |

积分回答的原句：

> 查看会员中心或积分页面上的规则说明（通常会标注有效期或到期时间）；

结尾又提到可帮助梳理“如何查看积分明细与到期提醒”。这不是明确确认功能存在的直接句式，
但在服务当前系统的语境中，仍提供了无资料支持的页面/功能建议；“通常”和“具体入口以官方页面为准”
不能补足依据。不能因为开头说“无法确认”就将整段判为通过。

## 结论与下一步

认证本次已通过，当前发现的是回答生成质量缺口，而非检索未传入空集或重复调用。
模型确实收到空 snippets 及资料不足约束，却仍按常见产品经验补充建议。
这不证明所有空资料请求都会失败，也不证明其他场景长期稳定。

不启用尚未验收的依据审核器作在线保护，不通过改 FAQ 为错误回答补依据。
建议下一步针对“没有相关依据时不补特定系统页面或功能”的通用生成边界做小范围修正，
同时保留充分资料正例防止过度拒答；不要写积分、图书或电商专属关键词规则。
本轮只完成验收，未实施该修正。
