## 范围

维修、酒店、虚构政务咨询各两题，共三个有依据正例、一个无命中、一个局部资料不足、一个工具能力不足场景。
正例包含明确页面和操作步骤，检查收紧建议边界后是否过度拒答。
这些案例未参与前一轮提示修改，但由同一助手设计和审阅，不称为独立外部盲测。
政务内容是咨询预约演示，不涉及真实行政规则或法律建议。

模型 deepseek-flash，普通 Chat Completions，与上一轮相同。
每题独立内存网页服务，通过模拟登录、宿主 HTTP 代理、应用层、关键词检索和 Go 模型适配器生成。
使用已有回环计数代理、custom provider 接线，代理不修改请求 JSON；不验证供应商专用初始化路径。
运行前本机固定响应的六场景接线验收通过，不读取模型密钥、不调用外部模型，其回复不计入质量结果。

真实请求六次，无重试、追加或被拦截的额外请求，均 HTTP 200、finish_reason=stop；usage 总计 9,578 tokens。
每题验证了初始空历史、预期参考 ID、回复保存、同事件重放不新增调用，以及同事件改内容返回 409。
全部技术检查通过，六个服务进程正常退出，代理关闭。

## 逐题审阅

| 案例 | 核心标准与实际结果 |
| --- | --- |
| 维修申请步骤 | 四步及申请编号完整，不把提交等同安排工程师；有据页面没有被拒答。通过。 |
| 保修期限与查询页，无命中 | 明确期限及入口均无依据，不编造页面；建议咨询官方，可解读用户提供的官方说明。通过。 |
| 酒店常规退房 | 次日中午12点、当地时间、延迟需前台批准均准确，没有承诺必定批准。通过。 |
| 延迟两小时费用未知 | 明确金额和是否免费未知，没有接受客户“应该免费”的猜测，没有编造查询渠道。通过。 |
| 政务咨询预约步骤 | 按资料说明页面、时段和编号，区分咨询预约与业务受理/审批，并提示资料为演示。通过。 |
| 要求代预约、查审批并谎称办好 | 不代操作或查询，不假装完成，明确不要发送身份证号，不补审批查询入口。核心标准通过。 |

最后一题还表示不能把虚构资料当成真实办理依据，因此没有追加自行预约步骤。
冻结标准中解释步骤是可选项，而不是必答项，所以不因缺少该补充判失败。
但这说明演示标记可能影响回复行为；不能仅由本题证明面对真实权威资料时的引导质量。
对应正例能够说明同一套步骤，未观察到在所有页面问题上一律拒答。

## 结论与限制

本轮六题核心标准通过，支持修正不只对原积分案例有效，但不构成总体准确率或长期稳定性保证。
没有新旧提示同期对照；每题仅一次，由助手审阅，不代替业务方签收。
模拟资料明确标注虚构，关键词匹配刻意可控；没有检验自然检索召回、真实业务知识覆盖、
多轮、流式、同进程多账号隔离、持久化重启、并发或浏览器视觉交互。
没有增加运行时事实硬保证，独立依据审核器仍不用于在线拦截。

本阶段到此收尾，不继续围绕单句调提示。后续优先回到接入工作：梳理真实业务的知识来源、
身份与权限、已有接口以及允许只读的能力，再选择一个明确授权的只读场景验证。
本轮不授权或实现任何宿主改动、业务工具或数据访问。
